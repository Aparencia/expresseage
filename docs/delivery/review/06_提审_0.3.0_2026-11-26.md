## 2. 测试账号与审核体验路径

### 2.1 选择

选 **「无需登录账号即可使用」**：本程序没有账号/密码，审核员用自己的微信即可进入顾客端；不需要提供测试用户名与密码。

### 2.2 为什么还需要一个「测试兼职编号」

顾客下单前必须先绑定一名兼职（凭证是完整兼职编号，不是账号密码）。为了让审核员能走通「下单」主流程，请在版本描述里给出一个 **ACTIVE 的测试兼职编号**（如 `PXXXXXX`），该编号不是登录凭证、可随时在后台停用。

**提交前必须确认**：该测试兼职为 `ACTIVE`、编号准确、未绑定满额；审核结束后可在后台停用或解绑。

### 2.3 审核员体验路径（如后台有补充说明/备注字段，可整段粘贴）

```text
本小程序为校园快递代取工具，无账号密码。建议体验路径：启动页阅读并同意隐私政策 → 完善顾客资料（昵称必填，头像可跳过）→ 首页点「下单」→ 上传取件码截图（也可不传截图手填；有截图时站点/取件码可留空，由兼职按截图补全）→ 核对 → 选择服务与送达方式 → 提交。若首页提示先绑定兼职，请在「绑定兼职」输入测试编号 {{测试兼职编号}} 后绑定，再下单。接单端与开发者后台需要对应微信身份，无法在审核设备上切换，相关页面见随附截图。本程序不承载交易与账目，订单只记录取件与送达进度。
```

## 3. 小程序订单中心 path：留空

- 本程序为工具类信息与履约工具：**不承载交易、不涉及支付/资金、不产生账目**；订单状态只表达「待接单/已接单/已取件/已送达/已完成」等履约进度（CONTRACT §0/§6，D5/D6）。
- 因此 **不适用「交易类小程序订单中心 path」**，该字段留空；如审核追问，可回复：

```text
本小程序不涉及交易，无交易订单与账目；订单仅为校园快递代取的履约进度记录，因此不提交交易类订单中心 path。履约进度页为 pkg-customer/pages/order-detail/index（非交易订单中心）。
```
