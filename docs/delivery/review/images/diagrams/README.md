# 审核示意图（4 张 PNG + 生成脚本）

> 定位：提交微信小程序审核时随附的示意图（材料包 `docs/delivery/review/` 的 `images/diagrams/` 子目录）。
> 声明：**本目录全部为示意图，不含真实用户数据，不代表真机截图**；真实页面截图见同级 `../screenshots/`，由 `02_审核截图清单与图注.md` 逐张登记文件名、页面路径与图注。
> 零金额口径：本小程序只提供下单、接单与取件信息整理，**不涉及任何金钱交易**；全链路没有支付入口、没有账目字段、没有金钱计算（口径见 `docs/delivery/V4_REVIEW_MATERIALS.md` §0 / §2.4）。
> 维护：PNG 由 `build_diagrams.py` 生成，**不手改图片**；改文案先改脚本再重跑，并同步更新本说明。

## 2. 逐图说明

### 2.1 `01_审核材料索引图.png`
- **用途**：一张图讲清材料包里「提审页必填 → 随附图片资料 → 说明文档」三者的对应关系，供提交前一次性核对。
- **内容**：左列微信公众平台提审页必填 5 项（版本号 / 版本描述 / 功能页面 / 测试说明 / 加急理由）；中列 `images/screenshots/`（真实页面截图：顾客端 / 兼职端 / 开发者后台只读与测试 / 隐私与协议页面；以及微信后台声明截图）与 `images/diagrams/`（本目录示意图 4 张）；右列说明文档 6 份（`00`~`05`）；底部红线声明不代提审、不代填真实值。
- **口径来源**：`docs/delivery/V4_REVIEW_MATERIALS.md` §1（提审前置清单）、§5（提审证据留存表）；`AGENTS.md` §7（禁止清单与代操作边界）；`app.json`（功能页面路径）。
- **关键口径**：图片只给类别与目录、不写张数；文档名单以材料包实际 6 份为准；真实值只出现占位，真实 openid / appid / 邀请码 / 联系方式不落仓库。

### 2.2 `02_审核体验路径图.png`
- **用途**：向审核员说明三条体验泳道与页面路径，重点回答「一个微信号能否跑通」「后台为什么进不去」。
- **内容**：顾客泳道（隐私弹窗 → 身份选择 → 顾客首页 → 资料/编号 → 下单四步 → 订单详情 → 我的取件码）；兼职泳道（身份选择 → 激活 → 服务配置 → 代客下单 → 接单 → 已取件 → 送达 → 单量统计）；开发者泳道（后台总览 → 切换账号 → 识别失败复核 → 审计查询）＋右侧黄条/蓝条会话标识图例与三条要点。
- **口径来源**：`docs/delivery/V4_REVIEW_MATERIALS.md` §2.1 / §2.2 / §2.3；`app.json` 页面清单；`components/switch-bar`（黄条 `#FFF4CE` 真实只读、蓝条 `#E8F0FF` + `TEST` 角标）与 `shared/enums.js`（角色/状态文案）。
- **关键口径**：顾客可无截图手填（每单 0~10 张，D24 / D40）；兼职端可一个微信号单机完成代客下单→接单→取件→送达（绑定只能由顾客发起）；开发者后台仅 `ADMIN_OPENIDS` 白名单可进入，审核员以录屏与分步截图体验。

### 2.3 `03_隐私数据流图.png`
- **用途**：随隐私声明材料说明「采集什么 → 存在哪 → 多久删除」，供隐私对照表与审核备注引用。
- **内容**：三列数据流（采集 / 处理与存放（本机 / 云端）/ 留存与删除），四行数据项：取件码截图、昵称与头像、我的取件码（本机清单 · D57）、剪切板；底部为删除与注销链路。
- **口径来源**：`docs/privacy/隐私保护指引.md` §一（收集清单）、§三（保存期限与安全）、§五（用户权利）；`config/defaults.js`（截图留存 7 天、识别失败留存 30 天可配 7~30、本机取件码上限 50、查看临时链接约 5 分钟、切换会话 30 分钟）；`docs/delivery/V4_REVIEW_MATERIALS.md` §0。
- **关键口径**：截图识别在本机完成（端侧识别、截图不上传第三方）；仅识别失败时把去敏文字发 DeepSeek（不含原图 / 微信标识 / 联系方式 / 头像昵称）；失败原图进复核队列并逐次审计；本机取件码清单只存本机、不上传不共享、兼职端与后台（含只读）不可见；无截图可手填；注销 30 天内物理删除。

### 2.4 `04_零金额口径图.png`
- **用途**：向审核方直接论证「本程序不是交易/支付类产品」，随类目备案与业务说明提交。
- **内容**：左侧本程序状态机（7 状态）与两档服务类型、7 状态枚举；右侧「支付类产品（本程序没有）」对比示意（打叉节点）；底部三条口径（服务类型只表达做什么 / 状态机只表达履约进度 / 统计只有四类）。
- **口径来源**：`docs/delivery/V4_REVIEW_MATERIALS.md` §0 / §2.4；`shared/enums.js`（7 状态与 2 档服务类型）；`docs/contract/V4_CONTRACT.md` §5 / §6。
- **关键口径**：状态机只表达履约进度，没有支付、退款一类状态；服务类型只表达「做什么」，不含数量、记录或账目概念；统计只有单量、完成率、状态分布与异常数；全链路零金额。

## 3. 生成命令

```powershell
# 在本目录执行（Windows；需中文字体 C:/Windows/Fonts/msyh.ttc）
cd docs/delivery/review/images/diagrams
& "D:\AISI\dsh-data\.dsh\dsh-runtimes\dsh-primary-runtime\dependencies\python\python.exe" build_diagrams.py
```

- 环境：Python 3.12 + Pillow 12.3（捆绑运行时已装；无 Pillow 时先安装 Pillow）。
- 输出：白色背景、深灰 `#1F2937`、品牌绿 `#1F7A5C`、浅灰 `#6B7280`，宽度 2000px（2x 渲染，`dpi=192`），逐张自检 ≤600KB。
- 重生成后请用图片查看器抽查：中文无乱码、无重叠、无截断、箭头指向正确、底部「依据」行完整。

## 4. 边界与注意事项

- **示意图，不含真实用户数据，不代表真机截图**；不要把真实截图、真实编号、联系方式或邀请码贴进本目录。
- 图中页面路径均来自 `app.json`；页面改名或增删后须重跑脚本并同步本说明。
- 图中留存/上限数字均取自 `config/defaults.js` 与 `docs/privacy/隐私保护指引.md`；配置口径变更时先改文档与配置，再重跑本目录。
- 真实值在材料包中一律用占位符（`{{联系方式}}` / `{{审核邀请码}}` 等），由用户填写，agent 不代填。
