### 1.3 「本机取件码清单」（D57）为什么不新增后台声明项

- 事实：清单只存顾客本人设备（`utils/storage.js` 的 `PICKCODES_KEY='ex_college_v4.pickcodes'`，单一写口：`loadLocalCodes/addLocalCodes/removeLocalCode/setLocalCodeChecked/clearLocalCodes`），**零服务端集合/接口/字段、零上传、零外呼**；端侧识别见 `pages/customer/pickcodes/parts/local-ocr.js:pickImages`（`wx.chooseMedia` + `utils/ocr/wx-platform.js` 端侧 OCR；D64 起页面迁至主包）。
- 因此后台**不新增**信息类型：截图选择沿用「选中的照片或视频信息」「摄像头」；复制取件码沿用「剪切板」；清单本身在端内全文与补充文档披露即可（§一 项 20、§二「本机取件码清单只保存在这台手机上」条、§三「本机取件码清单不进入云端存储」条、§四「本机取件码清单不对外提供」条）。
- 边界（必须与文本一致）：不进日志/通知/分享卡片/URL；兼职端与开发者后台（含只读视角）均不可见；可随时删除单条或一键清空；换机/清缓存丢失；上限 50 条、按码去重。

## 2. `privacy_list ⊆ setting_list` 自检口径（提审平台检测）

- **机制**：平台按代码实际调用的隐私接口生成检测清单（`privacy_list`）；后台《用户隐私保护指引》的声明构成 `setting_list`。**`privacy_list` 必须被 `setting_list` 逐项覆盖**，漏项提审会被拦截（典型报错如 `api scope is not declared in the privacy agreement`）。
- **操作顺序**：①上传含隐私接口的体验版/提审版本 → ②提交审核时查看平台「隐私接口检测」清单 → ③在《用户隐私保护指引》逐项声明，用途写具体场景（照本表 §1 抄口径） → ④补充声明约 5 分钟后生效 → ⑤重新检测确认无缺项 → ⑥截图归档。
- **本项目预期声明面**：昵称+头像（同一项）、选中的照片或视频信息、摄像头、选中的文件、剪切板（「地址」如后台提供则如实勾选）；对应 §1.1 六行与 §1.2 不使用面。
- **最常见漏项**：①「剪切板」未声明（复制/粘贴直接报错）；②「选中的照片或视频信息/摄像头/选中的文件」三缺一；③「昵称、头像」只声明其一（后台是**同一项**）。
- **已写进清单**：`docs/privacy/发布前填写清单.md` §2.14（自检）与 §5.22（提审页核对），本表为两者的对照底稿。

## 3. DeepSeek 第三方披露口径（后台无「第三方服务/SDK」栏）

### 3.1 事实（先看事实，再写材料）

- 仅当截图识别**站点/取件码失败**时触发；由云函数 `cloudfunctions/api/handlers/ai/parseParcel.js` 统一外发，客户端只调 `api/modules/ai.js:parseParcel`（`ai.parseParcel`），**客户端不直连第三方**。
- 外发白名单唯一单源：`cloudfunctions/api/lib/ai/payload.js` 的 `AI_PAYLOAD_KEYS = ['ocrTextMasked','hintTrackingTail','role']`；云函数侧二次去敏；**不发原图**、不发微信账号标识、不发联系方式、不发头像/昵称；不用于训练。
- 降级与限额：单次约 8 秒超时（`config.aiFallback.timeoutMs`）、连续失败熔断（`cooldownMinutes`）、**不设每人每日次数**（`maxPerUserPerDay=0`，D40）、保留全应用日配额（`dailyQuota`）；配额用尽/冷却/开关关闭/服务不可用时**静默降级为手填**，不阻断下单。
- 失败留存：识别失败原图与复核记录默认 **30 天**（`config.recognitionFailureRetentionDays`，7~30 可配）；原图仅白名单开发者在复核页临时查看（`admin.getRecognitionFailure`，`getTempFileURL` 约 5 分钟 + 每次落 `FAILURE_IMAGE_VIEW` 审计），**原图不出本程序云存储**。

### 3.2 后台可写位置（三处，缺一不可；自开发小程序没有 SDK 栏，不硬填）

1. **「选中的照片或视频信息」的用途栏**（可粘贴）：
   `用于识别取件码截图中的站点与取件码。当本地识别站点或取件码失败时，仅把去敏后的截图文字提交第三方大模型服务（DeepSeek）做结构化识别辅助，结果只作预填建议；不发送原图、不发送微信账号标识/联系方式/头像/昵称，不用于训练；失败可手动填写，不阻断使用。`
2. **「信息对外提供」（如后台可编辑）**（可粘贴）：
   `识别失败兜底场景，向 DeepSeek API 提供去敏后的截图文字（不含原图与账号标识），仅用于本次识别、不用于训练；原图不对外提供。`
3. **补充文档**（`docs/privacy/补充文档.txt`，上传前只把 `__________` 替换为公开联系方式）与端内全文 §一 项 10、§四 例外 3——两处与上两条必须同一口径。

### 3.3 不得出现的表述

- 不得写「上传截图给第三方/第三方查看原图」（实际只发去敏文字，原图不出云存储）。
- 不得写「用于模型训练/优化服务」（实际不用于训练）。
- 不得把 DeepSeek 写成 SDK/插件（本小程序无第三方 SDK，自开发无该栏）。
- 不得在客户端或任何材料出现 Key 名以外的凭据值（`DEEPSEEK_API_KEY` 只存云函数环境变量，仓库只出现键名）。

### 3.4 代码证据

- 外发键集合：`cloudfunctions/api/lib/ai/payload.js:AI_PAYLOAD_KEYS`、`buildAiPayload`。
- 客户端零直连：`api/modules/ai.js` 只调 `client.call('ai.parseParcel', …)`；`grep -rn "api.deepseek.com\|DEEPSEEK_API_KEY\|deepseek-chat" --include=*.js api/ utils/ pages/ pkg-customer/ pkg-partner/ pkg-admin/ components/` 预期 **0 命中**（Key 只在云函数环境变量）。注：`AI_SOURCE='DEEPSEEK'`（`utils/recognize/index.js`）是识别结果来源的**枚举值**，不是网络外呼；不要把它当外呼证据，也不要在材料里引用为多终端点。
- 断言取数：`node tools/selftest.js`（AI 套件断言外发 payload 键集合 = 白名单）；**断言条数以真实输出为准，本表不写死**。
