## 0. 全文通用口径

- **零金额口径**：本小程序只提供下单、接单与取件信息整理，**不涉及任何金钱交易**；没有资金往来入口、没有账目字段、没有账目计算或对账环节；服务类型只表达"做什么"，不承载任何数量或金钱信息。
- 产品名称、简介、截图、审核备注、客服话术统一按上一条表述；任何材料不得暗示本程序具备资金往来或账目能力。
- **阶段口径（v2.1 起）**：材料面向「**体验版上传 → 提交审核 → 审核通过 → 发布 → 发布后清理**」的微信审核流程，不是开发联调阶段；提审版本 = 当前体验版 **v2.1（33 页，主包 8 + 顾客分包 5 + 兼职分包 9 + 后台分包 11）**。
- **备案口径（2026-11-03 用户确认）**：小程序备案**已完成**，不再是提审前置阻塞；仓库只记录状态与占位，**真实备案号、备案页截图只在用户后台与证据目录**。
- 隐私配置以代码与 `config` 当前值为准（`privacyVersion`、留存期限、头像上限等），逐项核对口径见 `docs/privacy/发布前填写清单.md` §3，本文件不另立数字。**隐私文本 = 定稿 v1.10（2026-11-03 用户确认）；`privacyVersion` 保持 `v4.0.0` 不升版（用户确认）。**
- **第三方 AI**：仅截图识别失败时，把**去敏 OCR 文本**发送给 DeepSeek 做辅助识别；**原图不发送第三方、不出本程序云存储**；失败记录进开发者复核队列（`[D16]`/`[D17]`）。
- **头像/昵称**：`chooseAvatar` 采集头像（自愿，可拒绝→默认头像）、`nickname` 输入采集昵称（必填、可改/手填）；仅当前 ACTIVE 绑定关系的对方可见，后台不展示头像、昵称脱敏（`[D19]`）。**D59 队内例外**：主兼职可在团队页看到本队子队员的编号与昵称（**不含头像**）。
- **转派与协作履约（v1.10 新增披露）**：已接单未取件的订单可能被转派给其他 ACTIVE 兼职（含绑定兼职的协作队员）；**承接方不获得顾客头像/昵称/客户档案**，顾客只看当前实际履约兼职的**编号**（`[D58]`/`[D59]`）。
- **账号切换**：平台**不能切换微信登录账号**；真实账号**只读**（黄条 + 服务端拒写 + 审计）、测试账号为后台合成账号（蓝条 + `TEST` 角标、只写测试数据、不计统计）（`[D14]`/`[D18]`）。
- **分享口径**：好友转发覆盖 19 个业务页（顾客/兼职业务页 + 身份选择页），后台 11 页零分享；**顾客「取件码」页（`[D64]`）与主兼职「我的团队」页（`[D59]`）不提供分享/转发**；朋友圈只挂身份选择/顾客首页/帮助 3 页单页预览（`[D36]`）；顾客绑定卡只带兼职编号、**不记录邀请关系**（`[D63]`）。
- D# 编号指向 `docs/contract/V4_CONTRACT.md` §13 的裁决表；未决事项统一在 §7 标"待用户裁决/填写"，不在此处自行拍板。

## 2. 分角色审核体验路径

> 前置：审核员用自己的微信号进入，无需提供密码；每个账号首次进入先过隐私弹窗（同意前不调用相册/摄像头/头像等隐私接口）。建议顺序：顾客 → 兼职 → 开发者后台演示。括号内为页面路径，便于截图定位。**当前提审版本 = 体验版 v2.1（33 页）。**

### 2.1 顾客侧（审核员本人微信号；资料与下单可自助）

1. 打开小程序 → `pages/launch/index`：隐私弹窗先读后同意（v1.10 文本含转派协作履约与队内昵称两项披露）；点"暂不同意"停在启动页，可再次查看/同意，不反复纠缠（QA P1/P10）。
2. `pages/role/index`：点「我是顾客」进入顾客首页。
3. `pages/customer/home/index`：绑定卡/服务说明/最近订单；主按钮文案为「**下单**」（D66，不再写"上传取件码截图"）。
4. `pages/profile/index`（顾客视图）：昵称必填（一键取微信昵称或手填，≤20 字）；头像可选（`chooseAvatar`，拒绝后显示默认头像，不阻断）；填苑/楼栋/宿舍号，手机尾号可留空；保存后显示顾客编号 `C-XXXX-XXXX`。**「我的」页含「分享给朋友」**（D63）：有 ACTIVE 绑定时生成该兼职的**绑定卡**（只带兼职编号、不含邀请者信息、未记录任何邀请关系）。
5. `pkg-customer/pages/bind/index`：只能由顾客输入完整兼职编号发起绑定；兼职分享的绑定卡统一落 `pages/launch/index?bind=` 并**先过隐私同意闸**，已同意隐私且资料完整时点「绑定这位兼职」自动完成绑定（D37/D38）；兼职端没有任何绑定入口（绑定方向 `[D20]`）；**顾客不能绑定子队员**（D59，输入子队员编号按"没有找到"处理）。若审核员没有可绑定的兼职，见 §2.5。
6. `pkg-customer/pages/order-create/index`（四步同页）：截图（相册/拍照/聊天三来源）→ 识别核对（可手填；多图/多码合并为同一张订单的多件，D23）→ 选服务类型与预约 → 确认提交。成功进订单详情。
7. `pkg-customer/pages/order-detail/index`：看进度/事件时间线、双方编号、取消/留言/删除记录；**一单多件时逐件显示「已取件/待取件」，部分取件显示「已取 n/m 件」**（D61）；**转派完成后显示当前实际履约兼职的编号**（`fulfillmentPartnerNo`，不含其头像/昵称；绑定关系不变，D58）。截图走临时链接。**页面没有任何资金往来或账目记录区域**，底部固定零金额声明。
8. `pages/customer/orders/index`：订单列表；部分取件行带「已取 n/m 件」小标签。

### 2.3 开发者侧（后台入口 → 真实只读 → 测试可写 → 复核 → 审计）

> 前置说明（审核材料必须如实写明）：后台只对云函数环境变量 `ADMIN_OPENIDS` 白名单内的微信号开放，无自助注册、无二维码/口令入口；**审核员微信号不在白名单，无法自行进入后台**。因此本段默认以运营者的**录屏 + 分步截图**提交；如审核方要求实机体验，按 §7 第 3 项另行安排。

1. 开发者白名单微信号打开小程序 → `pages/launch/index` 由 `user.bootstrap` 的 `isDeveloper=true` 自动分流到 `pkg-admin/pages/overview/index`（无需 `?admin=1`，白名单是唯一门槛）。
2. 总览：统计卡、异常工单、识别失败待复核摘要、审计区块、「切换账号」入口、后台消息。

### 2.4 为什么这些路径不涉及交易语义（审核说明可直接引用）

- 服务类型 = 名称 + 说明，没有数量、记录或账目概念；页面、接口返回体、截图、统计中都不含任何金钱字段或支付控件。
- 订单状态机只表达履约进度（提交→接单→取件→送达→完成/异常/取消）；没有"已支付/待支付/已退款"一类状态。
- **件级取件（D61）只是进度粒度**：逐件标记已取/撤销不改变订单状态语义，仍无任何数值或账目含义。
- **转派（D58）只是履约人变更**：订单号/顾客/绑定/宿舍标识/包裹内容/配送地址不变，顾客进度不受影响；不产生任何资金环节。
- **团队/子账号（D59）只是账号层级**：子队员为独立兼职账号，主兼职只做队内管理与转派，不涉及资金、不代收费用；顾客不能绑定子队员。
- **顾客分享绑定卡（D63）只是把兼职编号转发给同学**：卡片不含邀请者信息、不记录邀请关系、无任何利益承诺（不构成诱导分享/拉新）；取件码页与团队页不提供分享（D64/D59）。
- 统计只有单量、完成率、状态分布与异常数；没有收入、账期或报表指标。
- 没有第三方支付组件与支付回调，没有账目写入；取件码截图只用于识别与兼职核对。
- 因此审核演示不会出现任何资金往来或对账环节；隐私指引与用户协议使用同一口径。

### 2.5 审核员只有一台手机/一个微信号时怎么办

- 顾客侧可自助走通：隐私弹窗 → 资料（含头像/昵称可拒绝路径）→ 截图识别/手填 → 服务类型 → 无绑定时的绑定引导 → 我的/帮助/隐私全文/注销入口 → 取件码页。
- 兼职侧可自助走通完整履约（§2.2 第 5 步的代客下单不需要第二账号），也可单机演示件级取件、多站点按件分组、客户页筛选器、团队页发子码/按批次作废/移除成员。
- **必须双机的三项**：①订单转派（A 发起 → B 确认，§2.2 第 7 步）；②子邀请码激活（另一个微信号激活为子队员）；③顾客分享绑定卡 → 新顾客自动绑定（D63）。默认用**双机录屏 + 后台脱敏截图**提交；若审核方另行要求实机体验，按 §7 第 1 项安排。
- **绑定后的完整顾客下单与进度**需要"可被绑定的真实兼职编号"或录屏：默认用录屏 + 分步截图提交；是否在唯一环境提供主体自有的演示兼职，见 §7 第 2 项待用户裁决。
- 开发者后台受白名单限制，默认用录屏；**不建议**临时把审核员加入白名单（无法预知审核员 openid，且属控制台配置变更，只能用户执行）。
