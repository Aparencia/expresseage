# 嵌套对象 update 在 null 父级必崩（真实云 DB 拍平语义）

- 日期：2026-10-22 ｜ 来源：D1 单环境首次云端冒烟（`user.acceptPrivacy`）
- 现象：模拟器点「同意隐私政策」稳定报 `INTERNAL_ERROR`；云函数日志 `-502001`：`Cannot create field 'at' in element {privacyConsent: null}`。
- 根因：`users.privacyConsent` 初值 `null`；`dao.update(..., { privacyConsent: { version, at } })` 交给 `wx-server-sdk` 后被拍平成点路径 `$set`（`privacyConsent.at`），MongoDB 不允许在 `null` 上创建子字段 → 整次写入失败。
- 为什么本地全绿：fake DB 把嵌套对象当"整对象替换"，且不模拟空父级报错；4,151 条断言都跑不出真实 SDK 的拍平行为。
- 代价：首跑即卡死入口（隐私闸无法通过），且同类写点（`orders.exception` 恢复后置 `null` 再上报、`partners.serviceConfig` 等）都是潜伏故障。
- 修法：①`api/cleanup` 两个 `db/dao.js` 的 `update/updateWhere` 统一把普通对象值包成 `command.set`（整值替换，标量/Date/数组/既有指令透传）；②fake DB 复刻真实语义（对象拍平、空父级抛 `-502001`、`db.command.set` 支持）；③判据双向锁：dao 写入探针 + 真实语义反例 + `selftest-order-partner` G6b。
- 教训：凡"本地 fake 与真实 SDK/DB 行为不同"的地方，必须用真实云日志校正，并把差异写进 fake；只测业务逻辑不测写入语义，等于没测。
