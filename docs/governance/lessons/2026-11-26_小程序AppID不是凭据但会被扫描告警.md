# 小程序 AppID 不是凭据，但 GitHub 仍会报「Public leak」

- 日期：2026-11-26 ｜ 来源：GitHub Secret scanning 两条告警（Tencent WeChat API App ID，`project.config.json`）
- 事实：两条告警值都是 18 位 `wx` 开头的**小程序 AppID**（v2 快照的 `wxcb7…`、v4 开工期的 `wxf98c…`），不是 AppSecret；全历史 `git grep -i appsecret` 0 命中，`.env*` 与 `project.private.config.json` 均未入库。
- 为什么 AppID 公开：AppID 是应用标识（门牌），会出现在客户端请求与分享链接里；能换 access_token 的是 32 位 AppSecret，它只放云函数环境变量（`DEEPSEEK_API_KEY` 同理）。
- 处置：GitHub 告警 → Dismiss（reason 选 used in tests 或 false positive），评论写明「AppID is a public identifier; no AppSecret in repo or history」；**不动历史**（本仓纪律不改写历史），AppID 无法「换新」也不需轮换。
- 加固：AppSecret/外呼 Key 永不入库；`.env.example` 只登记键名；提交前扫一眼 diff 里有没有 32 位 secret 形态。
- 可选：若不想以后再被同一形态扫到，可把真实 appid 移到 `project.private.config.json`（不入库）、`project.config.json` 留占位——但 AppID 本身公开，属降噪不属安全修复。
- 判据：`git grep -i appsecret` 0 命中；`check.ps1` 四步通过。
- 教训：「告警 = 有泄露」不成立，先分辨标识与密钥；但也不能因为 AppID 公开就把 AppSecret 顺手写进配置。
