# 并发刷新里「晚到的旧响应」会把新数据盖回去

- 日期：2026-11-26 ｜ 来源：用户真机反馈「兼职工作台数据有时乱跳、显示之前的数据」
- 现象：标记取件/送达后行先变成新状态、几秒后又跳回旧状态（数量与 tabBar 红点同样回退）；切 chip 后看到上一个 chip 的单；弱网更明显，等下一轮轮询又自己好。
- 根因：主列表每次加载没有请求代次。30s 轮询 + 读动作自动重试（单次读最长在飞约 31s）+ 写后刷新/切 chip/搜索防抖/触底分页都会叠在同一个在飞请求上，旧响应晚到就按「当前筛选」上屏。
- 加重项：分页按请求前的列表快照合并 → 刷新插队后旧行复活；离页后迟到回调仍 `setData`、仍改红点；旧请求失败晚到会写一条假错误条（数据是好的却显示「检查网络后重试」）。
- 修法：每次加载领 `_loadToken` 代次，落地前用 `loadView.isStaleRequest`（代次/筛选/搜索词/已离页四合一）在 `applyResult`/`loadError`/`loadMore` 三条路径首行比对，旧包整包丢弃；分页迁入 `parts/load-flow` 共用同一守卫；`onUnload` 置 `_unloaded`。
- 判据：`selftest-order-workbench` P 组 13 条（乱序/切筛选/搜索词窗/分页复活/离页/迟到失败 + 真值表 + 接线静态闸）；变异电池去掉守卫 → P02/P03/P04/P05/P08 五条首红。
- 教训：任何「多个入口都会打同一个列表接口」的页面，先问一句「晚到的那包算谁的」——没有代次就没有正确的最后写入。
