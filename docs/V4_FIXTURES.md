## 3. 三条不可省的纪律（继承 v3 §6）

1. **每条新规则必须同批提交真机原文 fixture**。凭想象加标签词 = 误报换漏报；没有样本就不扩规则。
2. **每条新判据都要"装回去判红"**（变异测试）。判绿的变异 = 判据没牙，当场重写并补断言。
3. **识别引擎层保持不动**（分块/放大/比例等参数），除非真机读数要求；换云端 OCR 已被否（截图含姓名/手机号/地址/运单号 ⇒ 数据外发，CONTRACT §11.2）。

### 3.1 样本来源分两级，不许混用

| 级别 | 定义 | 能做什么 | 不能做什么 |
| :-- | :-- | :-- | :-- |
| **真机原文** | 用户真机运行识别后，从调试输出/识别结果里**原样**复制出的文本 | 可直接当规则依据、进指纹表、进自测 | — |
| **按截图转录** | 人看着截图手打/转述出的文本 | 只能作"待复验的形态假设"，帮助设计用例 | 不能当规则依据；不进指纹表；不参与端到端断言 |

- 教训：v1 早期把真机的**管道符 `|`** 转录成空格，导致"测的是另一件事"；v3 曾出现源码注释引用语料文件而文件长期不存在 ⇒ 识别规则在"没有样本依据"状态下被改。两条都不许在 v4 重演。

## 4. 取数与复核命令（数字/指纹一律来自命令输出）

**现状：`tools/fixtures/` 尚未建立**，下方前两条命令是**语料外置后**的复核规范（当前不适用）；当前有效命令只有第三条 `node tools/selftest-recognize.js`。外置落盘后，在仓库根执行（PowerShell / Node 均可）：

```powershell

node -e "const f=require('./tools/fixtures/v3-parse.js');const c=require('crypto');for(const k of ['D1','LINE_0926','TAIL_0926'])console.log(k,f[k].length,c.createHash('sha256').update(f[k],'utf8').digest('hex'))"

# 与 v3 原件逐字节一致（复制验收；输出应全为 true）
node -e "const v3=require('D:/Code/expresseage_college_v3/tools/parse-fixtures.js');const v4=require('./tools/fixtures/v3-parse.js');const c=require('crypto');const h=(s)=>c.createHash('sha256').update(s,'utf8').digest('hex');for(const k of ['D1','LINE_0926','TAIL_0926'])console.log(k,v4[k]===v3[k],h(v4[k])===v3.SHA[k])"

# 识别自测（读数以真实输出为准，不写死条数）
node tools/selftest-recognize.js
```

- 指纹口径：`sha256` 是**逐字节**指纹（UTF-8、无 BOM、保留原有空白与全角字符）；样本字符串长度与指纹必须同时登记。
- 读数口径：自测条数不写进文档；以 `node tools/selftest-recognize.js` 输出的通过/失败数为准（门禁要求"汇总行存在"）。

## 5. 指纹登记格式（fixture 文件内注释 + 本文件同步）

**语料外置时**，`tools/fixtures/v3-parse.js` 每个语料按以下字段登记（字段名固定，供自测与脚本读取）；当前**内联语料**只保留 `sha256` 指纹钉常量（`tools/selftest-recognize.js` 的 `CORPUS_*_SHA256`），不建 `SOURCE`/`LENGTH` 表：

```js
const SOURCE = {
  '<KEY>': {
    from: '<冻结源文件与定位方式（不写会漂移的行号）>',
    when: '<取证日期与场景>',
    shape: '<形态描述：整屏一行/码在标签前/无码等>'
  }
};
const SHA = { '<KEY>': '<sha256，来自 §4 命令输出>' };
const LENGTH = { '<KEY>': <字符数，来自 §4 命令输出> };
```

- 本文件 §2 表与语料文件（外置后为 `tools/fixtures/v3-parse.js`）**同源**：新增/变更语料时两处一起改，并同步 `tools/selftest-recognize.js` 的指纹钉；**当前内联形态**下，新增语料 = 在 `CORPUS_*` 常量里加真机原文 + 同步对应 `sha256` 常量与解析断言。
- 指纹钉住的位置：自测里对每组内联语料断言 `sha256(CORPUS_*) === CORPUS_*_SHA256`（外置后同时断言 `长度 === LENGTH[key]`）；**断言失败信息必须指出是"样本被改"还是"指纹被改"**。

## 6. 新增语料流程（按序；当前走内联路径）

1. **取证**：用户真机跑一次识别，把"识别原文"原样复制（不手打、不转述）；记录日期、机型/基础库版本、触发场景。
2. **源头脱敏**：姓名/手机号/运单号等一律按既有形态打码（如 `文*隽`、`138****0000`、单号保留形态但中间打码）；**不还原、不新增与识别无关的字段**；原文本身不落库、不进日志。
3. **程序化落盘**：把原文先存为临时 UTF-8 无 BOM 文本（不提交），用一次性脚本写入**内联语料常量**（`tools/selftest-recognize.js` 的 `CORPUS_*`；语料外置后改为写入 `tools/fixtures/v3-parse.js`）；脚本不留仓库。**禁止手抄**（空白/管道符/全角必须逐字节一致）。
4. **算指纹**：跑 §4 命令，把 `sha256` 写入对应 `CORPUS_*_SHA256` 常量（外置后同时写长度与 §5 格式、§2 补一行）；断言失败即样本或指纹被改。
5. **写判据**：先写"现状读数"断言（每条都能机器复现），再改规则；新规则与 fixture 同批提交。
6. **变异验证**：复制被测文件 → 注入变异（锚点尽量用 ASCII）→ 记录首红断言 → 逐字节还原 → `sha256` 比对一致 → 复跑全绿；证据写 `CHANGELOG.md`"工程细节"。
7. **回写**：`CHANGELOG.md` 记录语料新增/变更与指纹；涉及识别来源/字段/失败码时按 ENGINEERING §8.6 回写 CONTRACT/DATA_MODEL/隐私文本。

## 7. 反例与失败路径

| 症状 | 原因 | 处置 |
| :-- | :-- | :-- |
| 指纹对不上 | 有人改了样本（改空白也算） | **先查谁改了样本**；确认是有意识变更才更新指纹，并同步 §2 与自测 |
| 自测全绿但真机识别错 | 样本是转录/形态假设，或规则被改宽 | 退回"真机原文"重取证；补反例断言；跑变异确认判据有牙 |
| 新规则无 fixture | 凭想象加词/加标签 | 拒绝合入；先取证再改规则 |
| 变异后仍全绿 | 判据没牙/断言空集 | 当场补断言，记录"判绿=无牙"结论 |
| 语料含个人信息 | 取证时未源头脱敏 | 删除该样本、重新脱敏后录入；检查是否已进入日志/工单 |

## 8. 边界与验收

- **现状（批 12 后）**：语料已内联在 `tools/selftest-recognize.js`（`CORPUS_ONE`/`CORPUS_MULTI` + `sha256` 指纹钉 + 形态闸断言，随 `tools/selftest.js` 聚合执行）；**`tools/fixtures/` 未建立**，§4/§5 为**语料外置时**的登记规范（历史设计留档）；不伪造语料、不预写指纹。
- **语料外置时的验收**：v3 语料逐字节复制（§4 前两条命令全 `true`）；`SOURCE`/`LENGTH`/`SHA` 表登记；自测同时断言长度与指纹；新增规则均带语料与变异首红证据。
- **长期**：语料只增不删（废弃规则可删规则，不删样本）；指纹是基线，不是"现状快照"。
- 合规：样本不进小程序包、不进数据库、不进通知/分享；第三方 AI 只收去敏文本、不收原图（CONTRACT §11.2/§11.3）。
