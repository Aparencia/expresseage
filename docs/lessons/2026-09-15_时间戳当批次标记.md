# 时间戳不能当"批次/分组"标记（同毫秒会撞车）
现象：软删除整个档案时给档案与名下记录打**同一个 `deletedAt` 时间戳**，恢复时按该时间戳认领；结果"单独删过的那条记录"被连带复活——因为单独删除与档案删除发生在**同一毫秒**，两个时间戳相等（expresseage_college 2026-09-15 被 tools/selftest.js 当场抓到两个 FAIL）。
根因：时间戳是**时钟读数**，不是**身份**；同毫秒内多次不同操作无法区分。凡"这几条是一起发生的"语义，都需要唯一标识而不是时间值。
修法（实测）：额外打一个唯一**批次串**（如 `b_<ts>_<rand>`）落在每个成员上，恢复/撤销时按批次串精确匹配；时间戳只用于展示与排序。改完自测由 2 FAIL → 全绿。
下次定位：批量操作 + 撤销/恢复语义；"按时间相等"分组的地方；测试跑得越快越容易复现。

现象补充（同日 · 同类第二面：**时间戳当排序键 → 顺序不确定**）：取件清单"组内最新置顶"按 `createdAt` 降序排；同一毫秒创建的两条时间戳相等，排序结果无定义 ⇒ UI 顺序会随机变、自测随机红（自测当场抓到第 2 个 FAIL）。修法：排序函数加**唯一回退键**（`if (diff!==0) return diff; return a.id < b.id ? 1 : -1;`），并在自测里用**受控时钟**（临时覆盖 `Date.now`）制造确定间隔，才能真正验证"最新在前"。
一般规则：**凡是"相等就要有序"的场景，排序/分组键必须是全序（时间 + 唯一 id）**。
