# 变异体卫生：改→跑→还原会给出假红/假绿
现象：盘上文件逐字节恢复后 vitest 仍报上一个变异的失败（#28）——`--no-cache` 不够（vitest 4 把缓存写进 node_modules）；CONTROL 与 MUTANT 读数不在同一棵树 ⇒ 两侧结论不可比。
根因：测试运行器缓存 + 变异与对照的测量载体不一致。
修法（原项目实测协议）：每个变异体在**新解的干净副本**上跑（`git -c core.autocrlf=false archive` 落盘再解包）；**CONTROL 必须同一棵树取读数**；文本扫描类判据的"0 命中"必须点名仪器 + 双侧自证（R8.7 家族：先剥注释再扫）。
下次定位：变异体实验读数诡异；还原后仍红；对照结论可疑。
证据：batch04-primitives.md:41（#28）· batch07-unwired-10.md:91 · batch06-motion.md:286（R8.7）
来源：Entropydecrease 台账（变异体纪律 §3）· 2026-09-13 并入模板

**补记（2026-09-25 · v2 波 5 r4）**：造副本时"排除 `.git`"的写法会**连 `.gitignore` 一起排除**（`filter: p => !p.includes('.git')` 是对路径子串做匹配，`.gitignore` 也含这个子串）。后果不是"少了个文件"这么轻：`tools/check.js` 有一条判据专门查"`.env` 是否被 `.gitignore` 挡住"，于是**副本的门禁基线一开就是 exit 1 / 2 项 FAIL**——一个纯环境造成的**假红**，看上去却像"我这个变异把它改坏了"。
　写副本配方时：① 排除项要匹配**目录边界**（`!p.includes('/.git/')`），不要匹配裸子串；② **副本必须先跑一次 CONTROL（无变异）取基线**，基线不绿就不许进入变异阶段——这一步和"CONTROL 同树取读数"是同一个道理，只是发生在变异注入之前；③ 任务书里给的配方也算被审对象，本轮的这条坑正是主 agent 写给审查者的配方里的（r4 回执 §4 第 8 条）。
同族（v2 补齐互指）：`2026-09-17_变异不红的两种含义.md`（"不红"有三种含义：闸门装饰 / 判据缺失 / **变异没进去**）· `2026-09-20_变异脚本静默空跑.md`（PowerShell 侧的"没进去"）· `2026-09-19_空集上的全绿.md`（零命中≠通过）。
