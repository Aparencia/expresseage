# 2026-10-22 · 二选一入参要靠显式互斥校验，不能靠缺省分支猜

- 现象：批 7 前 `order.create` 兼职路径只认 `guest`；给已绑定顾客代客下单时没有 `bindingId` 入参，绑定顾客单被静默落成 guest（`customerId=''`），顾客列表/详情永远看不到这张单；新服务端上线时 `bindingId` 又会被严格白名单当未知字段拒。
- 根因：契约新增"已绑定顾客 / 新顾客二选一"后，服务端缺省分支默认走 guest；没有"同时给 / 都不给"的拒绝判据，也没有两种形态的顾客可见性断言。
- 处理：`bindingId` 与 `guest` 显式互斥（同时给或都不给 → `VALIDATION_FAILED`；顾客单传二者一律拒）；绑定路径身份/`customerNo`/dorm/`roomTag` 一次装配，`requestKey` 归属 `customerId`；`selftest-partner-orders` C/D 组锁，变异电池 M4/M5 回退即红。
- 教训：①"二选一"必须在服务端首行做互斥校验，否则缺省分支会静默改变数据形态；②新增入参要同步白名单、契约、断言三处，缺一处就"接收但不生效"；③代客单两种形态的顾客可见性差异（能看见 / 无访问路径）要有端到端断言。
