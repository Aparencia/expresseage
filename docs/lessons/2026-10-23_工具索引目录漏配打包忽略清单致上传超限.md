# 2026-10-23 · 工具索引目录漏配打包忽略清单致上传超限

- 现象：微信开发者工具上传报 `代码包大小超过限制,main package source size 6351KB exceed max limit 2048KB`（07:18 与 07:49 两次读数一致）；主包业务代码编译后仅约 310KB，与被拒读数差 20 倍。
- 根因：仓库根 `.dsh-code-index/`（工具代码索引缓存，9,655,629B）只写进 `.gitignore`，没有进 `project.config.json` 的 `packOptions.ignore`；开发者工具仍按工程目录收进包内，该 JSON 编译后 6,192,992B，与主包编译产物相加 6,503,424B = 6351KB，正好等于服务端读数。
- 证据：①开发者工具本地缓存 `pkgSize`（2026-10-22 16:38 上次成功上传）主包 `__APP__` = 193 文件 / 276,829B，证明忽略清单本身有效；②索引文件 2026-10-23 00:59 落地，此后两次上传均报 6351KB；③`JSON.stringify(JSON.parse('.dsh-code-index/45467aa9e6f0.json'))` = 6,192,992B，按缓存逐文件「编译后/源码」比例估算当前主包编译产物约 310,432B，两项相加与服务端读数一致。
- 教训：`.gitignore` 只管仓库边界，不管代码包边界；落在 `miniprogramRoot` 内的任何工具缓存/产物目录，必须同时登记 `packOptions.ignore`，两份清单同源维护。
- 落地：忽略清单补 `.dsh-code-index`、`coverage`、`*.log`；`docs/V4_ENGINEERING.md` §3.1/§3.2 回写；上传复验由用户点击（agent 不代传）。
