# 修边界规则只修一半，等于把 bug 换个方向（第二轮审查当场抓到）
现象（expresseage_college 2026-09-19 · 一图多码）：24 审查 R-04 指出"多码切段把**下一张卡片的标题**算进了上一条" → 我只改了**右边界**（`end`），左边界（`start`）照旧。第二轮独立审查用"只把两张卡片顺序对调"就复现了：上一条把**上一张的站点行**吃进自己 → **判错取件点**。而**旧实现在这三例上全是对的** —— 也就是说，我的修复引入了新的 P1。
根因：把"边界"当**一个点**改，而它天然是**一对**（起点 / 终点）；两个方向各有各的失效模式，只压住一边，另一边就从"侥幸没触发"变成"必然触发"。
修法：改边界/窗口规则时**两侧一起看**，并给**每一侧各写一条反例断言**（本次补了 2 条 R2-01 回归钉 + 1 条残留钉，且这三条能分别打红左右两侧）；修完必须用**审查者给的原始反例**再跑一遍，而不是自己另造一个"更像成功"的例子。
更深一层：**幸存的正确性是靠规则顺序白捡的** —— 样本 S1 当时没暴露，只因 R5(`21栋`) 恰好排在 R7(`22栋`) 前面。只要"通过"依赖两条规则的相对顺序，就值得写一条断言把顺序钉死。
下次定位：边界类修复后"换个数据顺序 / 换个版面"就出错；审查说"只修了一半"；反例断言只覆盖了一个方向。
