# 教训 · 守卫的语料覆盖面必须与契约一样宽（不然守卫只在"你想到的写法"上有效）
**发生**（v1 · 2026-09-22 · 楼区门牌批）：同一个"静默错解"洞被三轮独立审查**打回三次**，洞的边界每次都比上轮修复面更宽 —— r1 只拦"纯楼区码"（`D11-522` 含横杠就短路）｜r2 改成"首字母须在枚举内"（洞挪到 21 个非枚举字母）｜r3 改成"须有分隔符"（洞又挪到 `号楼` 量词整类，而 `APIS.md` 已写"一律拒" ⇒ **契约说拒、实测接受**）。三次都是"**我只测了自己想到的那一种写法**"。
**根因**：守卫声明的输入形态是**契约级**的（多 token / 带分隔符 / 各段可缺 / 量词变体……），而语料只覆盖脑子里那一种写法 ⇒ **覆盖面缺口与代码缺陷长得一模一样：跑起来全绿**。
**规矩（v2 起生效）**
1. 守卫的**语料**必须与它声明的**契约**同宽：契约里写了 N 种形态，语料至少每种一条 —— 且必须是**能走到守卫内部**的最小样本（⚠️ 本例：**单 token 会走 ⓪ 分支、碰不到守卫 ⇒ 用单 token 测得假绿**，这正是三次漏网的原因）。
2. 每条语料配一条**回归钉子**进自测，断言名里点明**是哪种形态**（"多 token 形式"而不是"边界用例"）。
3. 判据的覆盖面本身要有**可数清单**：写不出清单 = 没核过覆盖面（同族：`2026-09-19_空集上的全绿.md`）。
**下次定位**：一个已"修好三次"的洞又漏；同一主题的自测只有一种输入写法；断言名写着"边界用例"这种不带形态的词；**契约文档说"一律拒"而实测接受**。
**同族**：`2026-09-11_规则与样例分叉.md`（规则与样例不同源）· `2026-09-17_变异不红的两种含义.md`（闸门是装饰 / 判据没覆盖）· `2026-09-19_空集上的全绿.md`（没测到也算绿）。
