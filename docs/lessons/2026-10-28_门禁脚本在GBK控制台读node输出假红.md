# 2026-10-28 · 门禁脚本在 GBK 控制台把 node 输出读成乱码 → 4 步假红

- 现象：`powershell -File check.ps1` 四步全部真实 PASS，却报「FAIL 缺或未命中汇总行」，退出码 1；`tools/check.js`/`check-docs.js`/`zero-money-scan.js`/`selftest.js` 单独跑都绿。
- 根因：Windows PowerShell 5.1 捕获原生程序输出时按 `[Console]::OutputEncoding`（本机默认 GBK/cp936）解码，而 node 输出 UTF-8 中文；`check.ps1` 用 `& node ... | Tee-Object` 收流后拿中文汇总行做正则匹配，字节被解成乱码 → 永不命中。终端里看到的乱码只是表象，假红在变量里。
- 教训：「门禁真实输出」的前提是**字符口径一致**——跨进程中文输出不能被控制台默认编码污染；同一脚本在不同控制台（Windows Terminal GBK / pwsh 7 UTF-8）会给出相反结论，不能只信一次终端显示。
- 落地：`check.ps1` 开头显式 `[Console]::OutputEncoding = [Text.Encoding]::UTF8`（失败不抛）；之后恒为 4 步 PASS 退出码 0；`gate.ps1` 行数口径交验（git blob vs 全文本）同理防编码漂移。
