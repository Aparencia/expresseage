# 集合名手打拼错：创建成功、首次读写才炸（-502005）

- 日期：2026-10-22 ｜ 来源：D1 单环境首次云端冒烟（开发者后台「总览」）
- 现象：总览页横幅「没连上服务器，先检查网络」，点重试无效；控制台集合列表看起来 14 个"都在"。
- 根因：控制台手建的集合名拼错为 `inbitation_codes`（正确 `invitation_codes`）；代码按唯一源 `shared/collections.js` 查询时报 `-502005 database collection not exists`，被收敛成 `INTERNAL_ERROR`。拼错的集合没有代码引用，创建/核对时都不会暴露。
- 代价：仪表盘整页失败，且后台统一把 `INTERNAL_ERROR` 展示为网络文案，排查方向被带偏（靠新加的云端异常详情日志才定位）。
- 修法：确认空后删除拼错集合 → 按 `docs/V4_ENGINEERING.md` §4.6 名字逐个复制新建 → 补权限（所有用户不可读写）与索引（如 `uk_code`）→ 重试。
- 教训：控制台手输的结构名（集合/索引/环境变量键）一律以代码唯一源为准逐个复制；`admin.bootstrap` 的 `missingCollections: []` 是唯一可靠的环境自检，不能拿"集合列表看着齐全"代替。
