# 2026-10-22 · 契约声明的入参被"接收但不落库"=静默丢弃

- 现象：DATA_MODEL §7.3 明确 `order.markPicked/markDelivered/order.correct/order.undo` 入参含 `batchActionId?`，但 handler 从不读取 → 首红断言 `[ok,batchActionId]` 实际 `[true,null]`；批量循环的"同批 id"在库里完全不可见，撤销/审计无法按批次核对。
- 根因：通用动作引擎 `runOrderAction` 只消费状态机需要的字段；契约新增的"元数据入参"没有对应落库点，测试若只断言响应 `ok` 会全绿。
- 处理：引擎按动作白名单接收 + 形态闸 `^[A-Za-z0-9_-]{1,32}$`（非法 `VALIDATION_FAILED` 零落库）+ 事务内写 `orders.batchActionId`；缺省写 `''` 清旧批次归属；`selftest-order-partner` C7~C12/D5/E12/F10 锁定，变异电池 M2 回退即红 6 项。
- 教训：①契约里出现的每个入参都要有"落库/事件/响应"至少一处可观测落点，否则等于没实现；②行为套只测 `ok` 不足以发现"接收但丢弃"，要断言库内字段与事件 payload；③批量语义的判据应同时锁"逐单 ok"与"同批 id 可聚合"。
