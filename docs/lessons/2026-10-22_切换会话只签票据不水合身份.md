# 切换会话只签票据、不水合身份 → 测试账号显示「待激活/资料未完善」

- 日期：2026-10-22 ｜ 来源：D1 单环境真机冒烟（开发者用后台测试顾客/兼职账号做单机验收）
- 现象：进入测试顾客会话后首页提示「还差苑/楼栋/宿舍号」、测试兼职「我的」显示「待激活」且无兼职编号；用户据此认为测试账号「无法激活、无法绑定」（激活入口对测试账号本就走不通）。
- 根因：`pkg-admin/pages/account-switch/index.js` 的 `startView` 只 `store.setViewContext(viewContext)` 就 `reLaunch`，从未拉 `user.bootstrap`；页面继续用开发者自己的空身份（roles=[]、customer/partner=null）渲染目标账号。且 `store.hydrateFromBootstrap` 会用服务端 `viewContext`（永不回票据）整块覆盖本地 viewContext → 会话内任何一次水合都会丢 `viewTicket`，后续请求失去切换身份。
- 修法：新建 `utils/session.js` 统一进入/退出——进入：写 viewContext → `user.bootstrap` → `hydrateFromBootstrap` → reLaunch；退出：`viewAsEnd` → 清 viewContext → 再 bootstrap 复位开发者身份；`store.hydrateFromBootstrap` 的 viewContext 分支保留本地票据、其余字段以服务端为准（服务端不回票据是口径）。判据：`selftest-switch` §1.3 新增 23 条（顺序/票据/失败不阻断/退出复位）+ `selftest-testaccount` §1.3 18 条固定测试对端到端（创建→切会话→直接绑定→双向可见→激活被拒）；变异三处首红：顺序调换 4 条、覆盖票据 1 条、页面直连 1 条。
- 教训：**「签发票据」≠「页面数据就绪」**——代理身份切换必须同时水合目标身份快照；只存内存的票据在"服务端不回票据"的 DTO 里必须显式保留，否则水合一次就把身份切换弄丢。
