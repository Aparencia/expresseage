# 变异"不红"有三种含义，必须分开（文件名保留原名"两种"，第三种是 2026-09-25 补的）
现象（expresseage_college · 2026-09-17 · #2 识别返工）：为落实用户给的规则"取件码往往较短，编号/电话等较长"新增了一道长度闸（数字位分档）。按纪律做变异证伪，结果**四处变异全都不红**（长度闸短路 / 中长档放宽 / 短码档放宽 / 字母位上限拿掉），当时差点写成"判据没牙、算了"。
含义一 **闸门是装饰**：长度闸排在 `CODE_SHAPE = /^[A-Za-z0-9][A-Za-z0-9\-_#]{1,19}$/` 的 **20 字上限**后面，永远轮不到它——14 位运单号在形状关就被拒，长度闸改不改都一样。修法：把长度约束**收敛到一处**（`CODE_SHAPE` 去掉长度、只留字符类），长度由 `isCodeLength` 单独裁决 → 再变异，立刻红。
含义二 **判据没覆盖**：字母位上限确实无判别力，因为当时没有"只有它能挡"的样本（8 位纯数字被形状正则挡住、13 位运单号被数字位挡住）。修法：构造**只有该闸能挡**的输入（`取件码: ABCD12345678`，数字位在档内 + 4 字母）→ 变异立刻红。
附带一条（标签取值的结尾边界断言 `(?![\dA-Za-z\-_#])`）**两者都不是**：去掉它行为完全不变（截断后的值同样过不了长度闸）→ 按"要么有牙、要么删"直接删除，并留注释说明"变异实验证明其无判别力"。
含义三（**v2 · 2026-09-25 波 5 r4 装配批补上**）**变异根本没进去**：注入脚本的锚点写成 `'\n'` 结尾，而目标文件是 **CRLF** ⇒ `String.replace` 静默没命中，"变异后仍然判绿"看着像在证明盲区，实际**什么都没测**（同一条读数第一次交付时就作废了，重写锚点才拿到真读数）。修法：注入后必须断言内容确实变了（`if (mut === orig) 打印"读数作废"并停`），换行按文件真实行尾处理——**行级正则只换行内容、不动行尾**最稳。⚠️ 2026-09-25 再补一刀（C 条修复时亲踩）：**"内容变了" ≠ "注入生效"** —— 那天我的"盘上核实"查的是**两版都有的那行**（`const hit = stations.matchBuiltinStation(text);`），于是核实"通过"而注入其实空跑，差点把假绿交付；凭据必须换成**只在变异版本里才存在**的片段（例：`stationName: text` 在盘上的出现次数 **0 → 1**），且**算了 `applied` 就必须把它打印出来**——只算不印 = 没有凭据。
纪律：变异不红**先分清是"闸门装饰 / 判据缺失 / 变异空跑"三种里的哪一种**，三者处置完全不同，不许挑一个蒙过去；也不许把无判别力的保护留在代码里冒充防线。（**反向也管**：变异**红了也要问"红的原因成不成立"** —— 注入把不相关的断言一起打红、或红在意料之外的条数上，都要先解释再采信；2026-09-25 的审查里 M2 就出现过"崩在中段、由计数闸兜住"的红。）
同族：`2026-09-20_变异脚本静默空跑.md`（PowerShell 侧的同一种"空跑"，走的是 `$ErrorActionPreference` + 相对路径那条链）· `2026-09-11_变异体卫生.md`（还原后仍红 = 载体不同树）· `2026-09-19_空集上的全绿.md`（零命中/全绿其实是没测）。
