# UTF-16LE 编码破坏与 PS 5.1 编码陷阱
现象：PS 5.1 用 `>` / `2>` 重定向写出的报告/日志，被 node/git/解析器读成乱码或"0 内容"；clippy 输出被按 UTF-16LE 解析成"0 诊断"假绿（P-3）；PS 5.1 读无 BOM UTF-8 脚本按 GBK 解析并吞换行（#34，收口评审 M-7 实测）。
根因：PS 5.1 重定向默认 UTF-16LE；无 BOM UTF-8 按系统码页误读。
修法（原项目实测）：报告/数据文件由探针脚本自己 `writeFileSync(utf8)` 写，**不用 PS 重定向**；中文/反引号参数一律落盘成脚本再执行（P-50）；跨工具交接的 .ps1 存 UTF-8 带 BOM。
下次定位：报告"0 内容/0 诊断"却行为不对；脚本在另一工具里乱码；含 `>`/`2>` 重定向。
