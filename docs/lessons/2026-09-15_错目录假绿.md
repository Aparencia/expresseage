# 工作目录错 = 判定命令假绿（"文件不存在"与"反向成功"印成同一句话）
现象：在母版根 `…\expresseage` 跑 `node migrations/xxx.js` → `MODULE_NOT_FOUND`；而验证命令 `fs.existsSync(p) ? … : '(根键不存在 = 与 up 之前一致)'` 因为**同样找不到文件**，照样印出"通过"那句 —— 环境错与结论一致无法区分（expresseage_college 2026-09-15 22 卡迁移空跑实测）。
根因：命令用相对路径、无人校验 cwd；判定文案把"文件缺失"这一种状态同时当成 pass 条件与 fail 条件。
修法（实测）：① 给人跑的命令块**第一行锁目录**（`cd <绝对路径>`），命令内断言"我在对的目录"（`Test-Path .\check.ps1` / `fs.existsSync('utils/migrate.js')`）② 判定输出必须**同时打印 cwd 与判定依据**，禁止只印结论 ③ 同一分支既可能表示"通过"又可能表示"环境错"时，拆成两种输出 + 非 0 退出码。
下次定位：命令报"找不到文件"却伴随"通过/一致"字样；母版 + 子项目并存的工作区里跑脚本。
来源：expresseage_college · 2026-09-15 · 22 卡迁移空跑（人执行）

现象补充（同日 · 同一根因的另一面：**调用形式错 → 假红**）：`powershell -File gate.ps1 -ScopeFiles "a","b","c"` —— `-File` 不解析逗号列表，`"a,b,c"` 被当成**一个**字符串塞给 `[string[]]`；于是只有第一个文件名靠反向通配 `$_ -like "$f*"` 蒙对，其余全判"越界" ⇒ 机械门禁假红（批 0 实测）。修法：数组参数别走 `-File`——用 `& .\gate.ps1 -ScopeFiles @('a','b','c')`（当前会话内调用）或 `powershell -Command "& '.\gate.ps1' -ScopeFiles @('a','b')"`。
下次定位（补充）：门禁/脚本报"越界/不匹配"，但同一命令换成**数组字面量**重跑即转绿 ⇒ 别去改代码，先查参数传递形式。

现象补充（同日 · 第三个同类面：**路径转义 / 编码让工具读数失效**）：`git diff --name-only`（及 `status --porcelain`）默认 `core.quotepath=true`，**中文文件名被输出成 `"docs/..._\351\224\231.md"`（含引号）** ⇒ ① 范围校验把合法文件判成"越界"（假红）② `Test-Path` 直接报 `Illegal characters in path`。修法：脚本里所有 `git diff/status` 一律加 `-c core.quotepath=false`（本项目已修 `gate.ps1` 并在原位留注释）。相关坑：用 write/edit 工具改过的 `.ps1` 会**丢 UTF-8 BOM**，PS 5.1 随即按 GBK 解析而崩 —— `tools/check.js` 第 8 条会机械拦下，别靠人眼。

现象补充（同日 · 第四个同类面：**假阴性**）：排查 24 卡审查的 R-08 时我用了 `Select-String -Path docs -Pattern X` —— `-Path` 只当**文件/通配符**用、**不递归目录**，于是 `listParcels/archiveDoneParcels/unarchiveParcel/archivedItems` 四个符号全报"不存在"，差点让我照着错报告去改**本来正确**的文档（换命令复核后：`APIS.md:27` 明明有 `archiveDoneParcels`）。修法：搜目录用 grep 工具 / `grep -rn` / `Get-ChildItem -Recurse | Select-String`；**任何"某符号全仓不存在"的结论，换一种搜索方式复核后再下判断**。
