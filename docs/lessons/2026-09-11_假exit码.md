# 假 exit 码：退出码被吞、截断或伪造
现象：命令失败却报"通过"；`$?` 为 true 但 `$LASTEXITCODE` 非 0；`| Select-Object -First N` 截断输出后 `$LASTEXITCODE` 变 -1；`$ErrorActionPreference='Stop'` + 原生命令写 stderr ⇒ NativeCommandError 吞掉退出码与全部输出（#94）。
根因：PS `$?` 只反映上一句是否出错；管道截断会掐断上游进程；重定向收尾改变语义。
修法（原项目实测纪律，batch08-groundwork-3.md:14）：① 绝不让 `2>$null` / `2>&1 |` 做 pwsh 的最后一条语句；② 判 exit code ⇒ 单独裸跑 + 立刻读 `$LASTEXITCODE`；stderr 需保留时用 `2>file` 分离重定向，绝不用 `2>&1 | …`（batch00b-icon-set.md:72）。
下次定位：DoD/门禁判定处；"没报错"被当成"通过"。
