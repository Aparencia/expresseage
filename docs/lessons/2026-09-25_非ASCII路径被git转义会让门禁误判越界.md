# 教训 · 非 ASCII 路径会让 git 输出变成转义串（门禁据此误判"越界"）
**发生**：2026-09-25 `gate.ps1` 的范围判据用 `git status --porcelain -uall` 取变更文件；一个中文名文件被输出成 `"docs/lessons/2026-09-25_\345\271\266\350\241\214…md"`（带双引号 + **八进制转义**）⇒ 去掉引号后仍是转义串 ⇒ 前缀匹配 `docs/` 失败 ⇒ 报 `[FAIL] 越界`（**假红**，而且看起来完全像"有人越界"）。
**根因**：git 默认 `core.quotepath=true`，对非 ASCII 路径做 C 风格转义 —— 那不是文件名的真实字节。解析 git 输出的脚本若按转义串做匹配/比较，一律错。
**规矩（v2 起生效）**
1. 任何**解析 git 输出**的脚本一律写 `git -c core.quotepath=false <cmd>`（本项目文件名大量含中文 ⇒ 这条必撞）。
2. 判据引入"路径"当输入时，先用一个**中文名文件**实测一次（`docs/lessons/` 下随手一个即可）。
3. 门禁报某文件越界、而终端里文件名带 `\3xx` 转义 ⇒ 先怀疑这条，别去改文件。
**下次定位**：`git status --short` 人眼对一遍；门禁的文件清单里出现 `\3xx` 或带引号 ⇒ 就是它。
**同一次会话里的第三种形态**：`git ls-files --others`（漏改）让 `Test-Path` 抛 `Illegal characters in path`，而脚本头是 `$ErrorActionPreference='Stop'` ⇒ **在汇总行之前直接终止**（打印停在中间、exit 1）——它长得像"门禁红"，其实**一条判据都没判完**。⇒ 规矩 4：解析 git 输出的**每一处**都要 quotepath=false（漏一处就等于全漏）；规矩 5：门禁的输出若缺汇总行，一律当"读数作废"，不许当红/绿用（教训卡 `2026-09-20_变异脚本静默空跑.md` 同族）。
