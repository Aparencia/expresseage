# 在空集上跑出"全绿"（判据一条数据都没覆盖，比没跑更危险）

现象（2026-09-17 站点库）：25 卡情景走查情景 12/13 **全部"通过"**，其实脚本把站点名硬编码成 `菜鸟驿站-3号楼`，
而库里落盘的是 `菜鸟驿站-3 号楼`（**带空格**，OCR 形态）→ 两条情景都在**空集**上跑，全绿却没覆盖一条数据。
讽刺的是：那一个空格**正是本功能要修的东西**（分组键是原字符串，差空格就裂成两组）。
根因：走查脚本的"输入"是它自己写死的字符串，而**真实数据来自另一条链路**（页面保存时 trim 首尾、保留内部空格）。
修法（已做/未做要分清）：脚本那处硬编码已改成**实际落盘的名字**；但**根因未消除** —— 目标名仍是写死的，
下次改名会再踩。**真正的修法**：目标名从库里实际派生的候选里取，并把"这次跑在什么数据上"打印出来。
下次定位：**"全绿"要先问它跑在几条数据上** —— 空集 / 全 `null` / 命不中任何分支，都会给绿灯。
　同族：错目录假绿 · 模拟器冒充真机 · `<view>` 上的 overflow 不能滑（都是"看起来验过了"）。
