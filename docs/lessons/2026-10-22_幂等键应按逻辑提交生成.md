# 2026-10-22 · 幂等键每次调用现生成 = 服务端幂等形同虚设

- 现象：下单页从不携带 `clientRequestId`，`api/client.js` 在**每次 `call()` 时现生成**一个新 id；弱网/超时后用户点「重试」，服务端拿到的是新键 → 若上一次其实已建单成功，就会**重复建单**。
- 根因：把幂等键当成「一次 HTTP 调用的追踪号」而不是「一次逻辑提交的幂等键」；服务端 `orders.requestKey` 做得再对，客户端每次换键也永远命中不了。
- 为何长期未发现：handler 单测都显式传 `clientRequestId`（例如 `order-000000000001`），测的是服务端；客户端 `api/client.js` 只被静态门禁覆盖「写动作不重试」，没有判据验证「重试复用同一键」。
- 修法：`call(action,data,opts)` 支持 `opts.clientRequestId`（16~32 位，非法静默回退）；页面进入 Step4 生成 submission id，内容指纹不变则重试复用、内容变更重生成、成功清空；单件走顶层 `recognition`、拆单逐件 `items[i].recognition`。
- 教训：①幂等键的**生命周期属于业务流程**（页面/视图模型），不能藏在请求层里每次现生成；②「服务端幂等」与「客户端复用同一键」必须成对断言，缺一半就是假安全；③用 transport 注入测客户端（不 mock 全局 wx）即可覆盖键复用。
- 落地：`api/client.js` 167 行、`parts/model.js` submission 生命周期纯件；`tools/selftest-order-flow.js` E/F 组断言（含拆单重试同键、内容变更换键）。
