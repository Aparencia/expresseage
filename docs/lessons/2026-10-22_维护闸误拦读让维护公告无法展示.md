# 2026-10-22 · 维护闸误拦读 → 维护公告永远无法展示

- 现象：维护模式开启后，端侧拿不到 `configPublic.maintenance`，只能显示"系统维护中"错误页；README/UX 承诺的"全屏公告 + 写接口拒绝"实际不可达。
- 根因：`middleware/auth.js` 的维护闸用 `spec.visibility === 'client'` 判断，把读（`user.bootstrap`/`config.getPublic`/`message.list`/`order.get`）一并拦成 `INVALID_STATE`；设计口径是"写拒绝、读与切换会话不受影响"（ENGINEERING §4.7 / UX_DEVELOPER §7.5），CONTRACT 未写细节 → 实现按最省事条件写。
- 教训：**闸口条件要按「动作语义」写，不能按「面向对象」写**——`visibility=client` 同时覆盖读与写，必须叠加 `spec.write`；否则依赖"先读配置再展示公告"的降级链路一定死锁。
- 落地：闸改 `visibility==='client' && spec.write && !developerNo`；`selftest-admin` A11~A15 锁「维护中读放行（bootstrap/config.getPublic/message.list/admin.stats）+ 写 `INVALID_STATE` + 关闭恢复」，`selftest-cloud` 同步旧断言；`selftest-message-pages` F 段锁端侧遮罩挂钩。
