# 教训 · grep 的行号先后 ≠ 代码结构：判"某字段在不在 `data` 里"必须看花括号闭合
**发生**：2026-09-25 我用 `Select-String -Pattern '^\s*(data:|chatKey:)'` 看到 `data: {` 在第 50 行、`chatKey: ''` 在第 75 行，就断定"`chatKey` 藏在 `data` 里"并删掉了它。**实际 `data` 在第 73 行就闭合了**，`chatRoomId` / `picking` / `chatKey` 都是**页面实例属性**（那一段的块首注释明写"刻意都不进 `data`"）。同一天我又用同样的方法误判了 `rebindTarget`（第二次，靠读结构才发现）。
**根因**：`Select-String` 给的是**行号**，不是**作用域**。缩进与顺序都不构成包含关系；两个模式各自的第一个命中点之间可以隔着任意个 `}`。
**代价**：`6602d20` 误删了一条合法声明（功能无害——代码先赋值后使用——但丢了显式声明与那块注释的意图）；更贵的是**回执里出现了一条"已完成"的假声明**（"移除了 data 里的死字段"），而它经不起 `git show` 复核。
**规矩（v2 起生效）**
1. 判"某字段在不在 `data` / 某个对象字面量里"⇒ **读那一段**（或 `node --check` 之外用真正的解析：`require` 后取 `data` 的键集合），⛔ 不许用 grep 行号推断。
2. 页面实例字段与 `data` 字段的区别是**一条花括号**的事，而两者在屏上的可见性截然不同（D3 就是靠这条）。凡涉及 D3 归位的判断，一律按"读结构"办。
3. 任何"我删了/我加了某字段"的回执，落盘前用一次 `git show <commit>` 或 `read` 回看**那一行**再写（同族：`2026-09-25_自述范围大于diff.md`）。
**下次定位**：想删/改一个"看起来是死字段"的东西时，先 `read` 它上下的 20 行，确认所在对象字面量的起止行。
**同族**：`2026-09-25_自述范围大于diff.md`（说的与 diff 不符）· `2026-09-11_数字口径与CRLF.md`（读数的口径）· `2026-09-19_插入时锚点行被吃掉.md`（编辑锚点选错行）
