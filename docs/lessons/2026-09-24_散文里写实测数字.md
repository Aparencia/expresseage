# 教训 · 散文里写实测数字，每次提交都会过期一次

**发生**：2026-09-23 r1 报告 R-14 点名"STATE 的数字混基线"→ 我当场按实测订正成 `40 文件 / +5,990 / −84`；**下一个提交就又错了**（实际 `44 / +6,539 / −116`）。同一天另有三组数字同时失真：断言"176"（实 207）、Must"12 条"（§9 后 14）、搬运"7 个逐字节"（实 6）。r2 审查（乙）一次性把它们全抓出来。
**与本卡家族的分工**：`2026-09-11_数字口径与CRLF.md` 管"数字怎么算才对"（口径、编码、行尾），`2026-09-11_stale产物读数.md` 管"测错了对象"；本卡管第三件事——**算对了的数字写进散文仍然会过期**，所以规则是"不写、改命令"。三者不互替。

**根因不是粗心，是结构**：只要把**实测数字**写进**散文**，它就跟着仓库一起变，而门禁看不见——`tools/check.js` 不读 STATE/CHANGELOG，v1 早就写过同一条教训（"STATE 被脚本排除在基线外 ⇒ 它的过期永远不会被哈希抓到"）。订正数字 = 追加一次债务，不是还债。

**规矩（v2 起生效）**：
1. 文档里**不写实测数字**（行数、文件数、断言条数、门禁项数、diff 规模），只写**取数命令**：
   `git diff --shortstat <锚点>..HEAD` ｜ `node tools/check.js | tail -2` ｜ `node tools/selftest.js | tail -2`
   ⚠️ **命令本身也要是对的口径**（`2026-09-11_数字口径与CRLF.md` 的元教训）：`tail` 是 Git-Bash 口径，PowerShell 侧写 `| Select-Object -Last 2`；这类读数只给人看，**判绿一律以退出码为准**。
2. 允许写死的只有**计划量**（预估分母、暂停线）和**契约常量**（`SCHEMA_VERSION=1`、存储键名）——它们由人定、不随提交漂移。
3. 状态类文档记"**最后一次人工核对日期 + 核对人是谁**"，不记当时读到的值。
4. 唯一例外：`tools/selftest.js` 的 `EXPECTED_ASSERTIONS`——它**故意**写死数字，因为脚本会拿它判红，过期变成响铃而不是静默。

**怎么记住**：数字进了散文，就没人会再去读它；数字进了命令，读者每次都会拿到真的。
