# `require` 一个迁移脚本 = 执行迁移（"只查语法"的念头会直接踩不可委托清单）
现象（expresseage_college 2026-09-19 · 柜号 v3 批 1）：我想"只做个语法自检"，写下
`node -e "require('./migrations/20260919_locker_no_up.js')"` —— 输出直接是 `[UP OK] schemaVersion=1 → 3`，
紧接着 down 脚本又把开发快照从 v3 回滚到 v2。**迁移脚本不是模块，是带副作用的可执行文件**：
`require` 就会跑完整个流程（读快照 → 备份 → 改盘），而这属于宪法"不可委托清单"（迁移只能人执行）。
根因：把"检查语法"和"执行逻辑"混在一个动作里；`--check` 才是语法，`require` 是运行。
修法：① 语法自检一律用 `node --check <file>`（或 `node -e "new Function(fs.readFileSync(...))"`），
**永远不要 require 会写盘的脚本**；② 迁移/发布/删数据这类脚本，agent 只能"给命令"，执行权交人；
③ 误跑后先取证再恢复：确认动的是哪个文件（本例是 gitignore 的开发快照，不是真机数据）→ 用脚本自己写的
备份还原 → **用 SHA256 证明逐字节一致** → 删掉误跑产生的多余备份（否则正式跑时"备份已存在 → 跳过"会掩盖）。
下次定位：任何"我只是想检查一下"的念头出现在**会写盘的脚本**上；输出里出现 `[OK] …→…` 这类业务回显（说明它真跑了）。
