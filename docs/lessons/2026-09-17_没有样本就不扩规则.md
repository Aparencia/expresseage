# 教训 · 没有样本就不扩规则：那是在拿误报换漏报
**发生**（v1 · 2026-09-17 · 站点识别）：一处已知残留（"版面 B 下共享行只能归上一条"）想改时被挡住 —— 改它需要"**标题自带地点 + 与上一条站点挤同一行**"的**真实样本**，而当时没有。
**规矩**：无真实样本扩规则 = **拿误报换漏报**。新规则一定会在某些真实形态上判错，而你没见过那些形态 ⇒ 用"看起来更聪明"换掉了"至少不猜"。
**翻案条件要写死**（不是"以后再说"）：写成"**真机识别原文里出现这种形态**"才动手，并指明**改哪里 + 加哪几条钉子**（本例：`utils/parse.js` 的段边界 + `selftest.js` 的三条回归钉）。
**配套**：站点 / 码型 / 段边界这类"猜形态"的规则，每次扩张都要有**样本入 fixtures**，与规则**同批**提交（否则下次没人知道这条规则凭什么长这样）。
**下次定位**：有人提议"顺手把规则放宽点，反正更全"；某条规则的注释写着"暂不支持 X"却没人能拿出 X 的真样本。
**同族**：`2026-09-11_规则与样例分叉.md`（规则与样例不同源）· `2026-09-19_空集上的全绿.md`（没测到就敢改）· `2026-09-19_只在新装机或真升级路径上炸.md`（没被跑过的分支等于没有的分支）。
