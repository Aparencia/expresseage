# 只在新装机 / 真升级路径上炸的缺陷（常规自测永远看不到）

现象（2026-09-17 #4 已取件）：旧 `migrate.up()` **无论传什么都返回空库** —— 日常自测读的是"已是当前版本的库"，
那条分支**从没被走过**；只有真机上的老库升级（v1→v2）才会触发，一旦触发就是**用户数据全没**。
根因：迁移/升级这类"一次性路径"既没有判据、也没被任何测试真正执行过 —— "自称的机械保证" ≠ "有牙的判据"。
修法：① `up()` 改成**保留式最小变换**（只补字段，其余一字不动）；② 新增第 4 步门禁 `../expresseage_college/tools/audit-migrate.js`
　（老库读得出 / 数据不丢 / 升级落盘 / 写失败不写坏盘）；③ 2026-09-19 又补两条：v2 库缺 `pickedAt` 必须报
　`PARCEL_INVALID:pickedAt`、该拒绝路径不写盘 —— 补之前 grep 发现那两条"保证"在 `tools/` 下**零命中**。
下次定位：凡是"只在首次运行 / 只在老数据 / 只在失败时才走"的分支，都问一句**"它被跑过吗？"**；
　没被跑过的分支等于没有的分支。看到注释自称"机械保证"就去 grep 它的判据在不在。
**v2 适用性（2026-09-25 收卡批加注）**：v2 **无 `migrations/`**、**无 `tools/audit-migrate.js`**（两处 `Test-Path` 实测均为 False）、`SCHEMA_VERSION=1` 且无历史版本链 ⇒ **本卡在 v2 无场景**，留给"将来第一次真实升版"；届时两条钉子（缺 `pickedAt` 必报 / 拒绝路径不写盘）按 v2 的 `utils/migrate.js` 重写，⛔ 不要照抄 v1 的脚本路径。
