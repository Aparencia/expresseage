# GUI 工具会静默改写入库的工程配置（必须 diff 后再提交）
现象：`project.config.json` 里已入库的 `appid` 被外部改掉——`wx04da13fa…` → `wxcb7e5b41…`，而 agent 本轮没碰过该文件；来源是**微信开发者工具**导入项目/切换登录账号时的写回（expresseage_college 2026-09-15 实测，`git status` 抓到一处 `M project.config.json`）。
根因：带 GUI 的工具把工程配置当自己的状态文件（appid、编译模式、setting 段都在里面），写回时不通知、不区分"人改"还是"工具改"。
修法（实测）：① 任何 `git status` 出现的**配置类改动**，提交前必须 `git diff` 人眼确认（本例靠它发现 appid 被换）② 机器私有/易变部分分离：`project.private.config.json` 加进 `.gitignore`，只把团队共享的字段留在入库文件里 ③ appid 这类"指向哪个线上主体"的值一旦变更，属于**产权级变更**——必须由人确认，不许 agent 顺手提交。
下次定位：`git status` 出现你没动过的配置文件；devtools/IDE/格式化器插件的自动写回。
