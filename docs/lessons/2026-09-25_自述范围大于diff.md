# 教训 · 自述范围大于 diff：把"改了八成"报成"改完了"
**发生**：2026-09-24 r3 报告的"现状"列（主 agent 填）写三条收口——R3-07「机械替换 7 处 errorText + **9 处** banner」、R3-09「两个都改成注入 ⇒ 已修」、§4 ③「`applyMultiParse`/`noteForRoom`/`labelOf` 全仓零残留」。r4 审查者按 `13f0294..HEAD` 逐条复算，三条全对不上：banner 实改 **8** 处，且**描述里自己点名的两处原封未动**（`saveDrafts` 的 `errorText`、`applyParse` 多码路径含 banner 的裸 `setData`）；签名确实改了但**调用点仍无参** ⇒ 函数体回落 `getApp()`；`labelOf` 有 7 处在用（被移除的是"页面方法"这一**形态**，不是符号）。订正回写在 r3 报告新增的 §6，原行不删。
**根因：计数由自己口报，而判据不看报告。** `check.js` 只看代码、`selftest` 只看行为，没有任何一道闸比对"报告里的数量"与"diff 里的实际数量" ⇒ 这类失真的表现**和诚实完全一样**：读起来具体、查起来有名字、跑门禁全绿。它比"改了 A 声称改了 B"更常见，也更容易自我放行——我确实改了一批，只是**顺手把"建好了出口"说成"接完了调用点"**。而 `R3-07` 漏掉的两处正是同一条描述里点了名的两处：**写结论时我在复述计划，不是复述结果。**
**规矩 1｜报告/文档里的数量词必须能由一条命令复算**，否则不写数字、写命令：替换类 ⇒ `grep -c "setDataMeasured" pages/recognize/index.js`；残留类 ⇒ `grep -rn "measureLayout" --include=*.js --include=*.wxml .`。**写不出对应命令的数量词，说明我自己也没核过。**
**规矩 2｜改完一批用"漏检项"收尾，不用"完成项"收尾**：把这一轮**点名要处理**的每个位置逐条 `grep` 一遍再写"已修"（本次两处漏网都有名字、有行号，查一次就看见）。
**规矩 3｜"已修"要带上它没覆盖的那部分**：写成"三个出口建好，`onToggleLines` 刻意不接（它改 `.mid` 内容，不影响上区）"才是可核查的陈述。
**规矩 4｜签名改造必须连调用点一起算完成**：只改函数签名不改调用方，判据不红、行为不变，属于**假收口**（与 `2026-09-17_变异不红的两种含义.md` 的"闸门是装饰"同一族）。
**规矩 5｜主 agent 填的"现状"列一律不可信**：r3 §5 诚实边界第 4 条已经写下这句话，r4 就照它抓出了四条。**下一名审查者的第一份工作，是复核上一轮那张表，不是信它。**（同一条也管**研究文档里的判决**：v1 `TD-030` 的 `RESEARCH.md` 判过"本样本本来就能认"，批 2 拿旧规则实测根本认不出 ⇒ **下判决前必须重跑一次实测** —— 判决也是自述。）
**下次定位**：一次装配后"报告说改了 N 处，diff 里只有 N−2 处"；或读者照报告去找某个收口点，发现它**仍然写着原始形态**。
**同族**：`2026-09-24_散文里写实测数字.md`（算对了也会过期）· `2026-09-19_插入时锚点行被吃掉.md`（操作看着成功、落盘的不是我要的）· `2026-09-15_模拟器冒充真机.md`（读数来源不明就不算数）。
**没有机器防线的部分**：这类错判据抓不到（判据不看报告措辞）⇒ 推论：**一个批次里没跑 r 轮，它的"已修"就只是说法**。
