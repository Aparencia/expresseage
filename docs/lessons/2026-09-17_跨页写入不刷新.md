# 跨页写入后"页面不刷新"：刷新责任不能绑在写入方身上
现象（expresseage_college 2026-09-17 真机反馈 #3，P1）：在「添加快递」页保存后自动返回客户档案页，**待办框看不到刚存的记录**，退出重进才出现。用户以为没存上，会重复录入。
根因：`../expresseage_college/pages/archive-detail/index.js`（**v1 树的路径**，v2 尚无这一页）只在 `onLoad` 读一次库，全文件没有 `onShow`。它原本靠"**谁写入谁负责刷新**"（本页内 7 处写入各自调 `load()`）维持显示——这个约定在"写入方就在本页"时一直够用。
本次新增了**跨页写入**（跳到 `pages/recognize` 写库后 `navigateBack` 回来），约定立刻失效。
一句话：**刷新责任绑在写入方身上，一旦写入方跨页就漏**。
修法（实测有效）：把责任放到**显示方**——页面 `onShow` 就重新读库（`archive-list`/`pickup-list` 本来就是这形态，
只有详情页漏了）。零依赖项目里这比"让写入方通知显示方"更稳：**新增任何跨页写入都不会再漏**。
**并固化成机械判据**（`tools/check.js` 第 9 条）：页面 js 里出现 `storage.list*/getCustomer` 却无 `onShow` → FAIL。
误报治理：确实是一次性表单的页面（本项目 = `pages/recognize`）列入**显式豁免表**并写理由，且豁免表**双向核对**
（页面已删或已有 onShow → 报"豁免过期"）——判据太宽会被整体关掉，豁免腐烂比误报更隐蔽。
下次定位：写完库"看不到新数据"；列表/详情要手动刷新才变；页面在导航栈里被其他页面改过数据。
