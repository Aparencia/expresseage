# V4_UX_CUSTOMER · v4 顾客端页面与交互设计

> 版本 v0.9（2026-10-21）｜依据 **CONTRACT v0.9**（下称 CONTRACT）｜范围：仅角色 `customer`
> 相关：`docs/V4_CONTRACT.md`（唯一口径源）、`docs/V4_UX_PARTNER.md`、`docs/V4_UX_DEVELOPER.md`、`docs/V4_DATA_MODEL.md`、`docs/V4_ENGINEERING.md`
> 优先级：**CONTRACT > 本文 > 其他**；字段/状态/页面路径/动作名/编号逐字引用 CONTRACT §3/§3.1/§5/§6/§7。本文新增提案集中在 §13，正文不藏「待定」。
> 用户硬口径（v0.7 起，v0.8/v0.9 继续有效）：**本程序不涉及任何费用收付**（不做交易、记账、分摊，不出现任何金钱字段/计算/文案）；服务只保留「类型名称 + 说明」。
> v0.8 三次修订：识别失败时可由**服务端**调用第三方 AI 做结构化兜底（只发去敏 OCR 文本、不发原图/openid），仍失败则进入**开发者复核队列**；客户端不直连第三方、AI 只做预填建议（CONTRACT §0 第 4 条/§4.3/D16/D17，详见 §4.3）。
> v0.9 四次修订：顾客/兼职采集**微信头像（`chooseAvatar`，可拒绝→默认头像）与微信昵称（`nickname` 输入，必填可改）**；**绑定双方互见头像/昵称，解绑/停用/注销后不再可见**；**只能顾客发起绑定**；`roomTag` **恒大写**（`D4-522A`）；开发者**切换账号**分「真实账号只读（黄条）/测试账号可写（蓝条+`TEST` 角标、仅测试数据）」（CONTRACT §1.3/§4.2/§8/§11/D18~D21）。
> 与 v3 的关系：复用 v3 **端侧 OCR 与解析行为/失败码口径**（`utils/ocr*.js`、`utils/parse*.js`，见 §4.3），**不依赖** `chatpick` 会话键；身份=微信登录 openid，归属=`orders.customerId`。

### 0.2 显示与文案规则
1. **零金钱（用户硬口径）**：界面只出现服务类型名称与说明；确认页底部固定一句「本程序不涉及任何费用收付」；不出现任何金钱字段、计算或文案（CONTRACT §0/§3）。
2. 时间：只用服务端 `serverTime` 判断今天/昨天与倒计时；进度/列表排序用 §0.1 显式时间戳。
3. 状态：文案只来自服务端 `status`/`exception.text`/`cancelReason`；颜色+文字双编码；前端不得「假装推进」。
4. **L3 敏感字段**（码/运单尾号/手机尾号）只允许「锚+键」配对（`D4-522A · 尾号6678 · 小王`）；不进分享/通知/日志。
5. 截图：仅下单确认页与订单详情页可见（临时 URL 5 分钟，过期自动续）；永不进分享/通知。
6. **`bindings.partnerNote` 顾客端永不展示**（任何页面/接口返回都不含）。
7. **唯一编号**：等宽独立行 + 复制按钮；展示 `C-XXXX-XXXX` / `P-XXX-XXX`，不缩写、不与其他数字混排；`partnerNo` 是绑定唯一凭据，`customerNo` 不作登录/绑定凭据。
8. 失败文案必须说清「发生了什么+下一步」（CONTRACT §8）；禁止「请稍后重试」式空话。
9. 文本上限（CONTRACT §5.2）：`orders.note`≤200、`deliveryNote`≤100、`bindings.partnerNote`≤100、`order_messages.text`≤200、`exception.text`≤200；`lockerNo`≤10 字符串；超限服务端返回 `VALIDATION_FAILED`。
10. **识别兜底（v0.8）**：OCR/规则失败时可自动请求 AI 兜底（≤8s、可取消、不阻塞手填）；AI 只做预填建议、手填优先不覆盖；失败静默降级并提示「已反馈开发者复核」；隐私披露见 §9.1/§9.6（CONTRACT §4.3/D16/D17）。
11. **头像与昵称（v0.9）**：头像圆形（列表 64rpx、资料/详情 96rpx），**无头像/加载失败一律默认头像**（昵称首字色块+浅底），不得空白/裂图；头像+昵称**成对展示**；**只向当前 ACTIVE 绑定的对方展示**，解绑/停用/注销后立即不再展示；**绑定前预览只显示昵称/编号、不显示头像**（头像在绑定成功后展示）；`onShow` 重新拉取、旧 fileId 失效回默认头像；分享卡片/通知/后台/日志不含头像与完整昵称（CONTRACT §4.2/§8/§11）。
12. **切换会话视觉（v0.9）**：`TEST_WRITE` 顶部蓝条 `测试账号 · {角色} {编号}（测试） · 由 {developerNo} 切换 · 退出` + 每页右上角 `TEST` 角标 + 隐藏分享/转发；`READONLY` 顶部黄条 + 写控件置灰/隐藏（服务端拒写）；退出回「切换账号」页（CONTRACT §1.3/§8/§10）。
### 0.3 页面五态模板
| 状态 | 判定 | 呈现 | 行为 |
| :-- | :-- | :-- | :-- |
| 默认 | 数据就绪 | 正常内容 | — |
| 加载 | 首屏请求中（≥300ms 才显示） | 骨架/居中 loading | 禁操作、保留返回 |
| 空 | 成功但无数据 | 文案+主行动按钮 | 可刷新 |
| 错误 | 网络/云函数失败 | 错误条或整页错误+重试 | 保留已填内容 |
| 无权限 | `FORBIDDEN`/非本人/角色不符 | 整页说明+出口 | 不展示业务数据 |
### 0.4 v3 能力继承边界
- 复用行为与失败码：`VK_UNSUPPORTED`/`VK_INIT_FAILED`/`IMAGE_DECODE_FAILED`/`NO_TEXT`；解析 `found` **恒带半成品**；回填=**只填空格+形态闸**（§4.3/§4.5）。
- 不复用会话键归属/取键回跳/内存桥（顾客端归属由登录身份+绑定关系决定，截图来源不依赖 `wx.openChatTool`）；「手输必须能存」底线保留：OCR/上传失败都可手填提交（`NEED_CODE` 见 §4.5）。
- **v0.7→v0.8 升级**：在 v3 端侧 OCR 阶梯与规则解析之后，新增「AI 兜底（服务端）→失败入开发者复核队列」两段；历史 v3 OCR 失败码/阶梯结论保留（§4.3）。
- **v0.9 四次修订**：新增微信头像/昵称采集与可见范围（§4.10/§9）、绑定方向（只能顾客发起，§6）、`roomTag` 恒大写（§7.3）、切换会话视觉（§2.4/§10）；旧「不收集头像 / 小写 roomTag」口径全部作废。

## 1. 首次旅程与关键用户故事
### 1.1 3 分钟首次旅程（资料 → 绑定 → 下单）
| 时间段 | 页面 | 顾客动作 | 系统动作 | 成功判据 |
| :-- | :-- | :-- | :-- | :-- |
| 0:00–0:15 | `pages/launch/index` | 打开、同意隐私弹窗 | `user.bootstrap` 建/取账号（**不返回 openid**，服务端由 OPENID 推导身份）；校验 `privacyVersion` | 已登录、已同意 |
| 0:15–0:50 | `pages/profile/index` 顾客视图 | 选择微信头像（可跳过）、确认昵称（一键填入，可改/手填）、填/确认资料 | （头像自愿）`upload.prepare({purpose:'AVATAR'})`→`customer.saveProfile` 写 `customers`（`displayName` **必填**、**首次生成 `customerNo`（幂等）**），`profileCompleted=true` | 昵称+苑/楼栋/宿舍号完整 + 已有顾客编号 |
| 0:50–1:20 | `pkg-customer/pages/bind/index` | 输入完整 `partnerNo`→绑定 | `bind.create` 校验 ACTIVE/限流→`bindings` ACTIVE→**分配 `roomTag`** | 绑定成功 |
| 1:20–2:20 | `pkg-customer/pages/order-create/index` | 上传截图→核对 | `upload.prepare`→压缩上传→OCR→解析预填→多码拆单 | ≥1 件字段合法 |
| 2:20–2:45 | 同上 Step3/4 | 选服务类型→预约/备注→提交 | 快照 `service{code,name}`→`orderNo`→`orders`+`order_events`（含 `customerNo/partnerNo` 快照） | 提交成功 |
| 2:45–3:00 | `pkg-customer/pages/order-detail/index` | 看「待接单」与双方编号 | 10s 轮询 | 进度可见、编号可见 |
- 保障：资料表单记忆上次选择；`partnerNo` 支持粘贴与容错；上传成功自动识别；服务默认第一项；主按钮常驻 ≥88rpx。
- 头像可拒绝/跳过：不阻断下单，使用默认头像（昵称首字色块）；**昵称必填**，未填不能完成资料（提示见 §7.2）。
### 1.2 首次进入判定树（`pages/launch/index` 唯一启动页）
```
登录 → 隐私版本检查 → 参数优先级：
 ?bind=partnerNo → 资料完整→bind 页；未完成→profile 顾客视图（完成后续跳 bind）
 ?orderNo=X      → 校验归属（source=CUSTOMER 且本人）→ order-detail；失败→订单列表
 开发者 isDeveloper=true → reLaunch 到 pkg-admin 后台（顾客端不做后台 UI）
 角色/资料/绑定判定：顾客默认；资料未完成→profile；无 ACTIVE 绑定→首页绑定引导；正常→首页
```
### 1.3 关键用户故事（验收按此逐条点检）
| 编号 | 作为顾客，我希望… | 验收要点 |
| :-- | :-- | :-- |
| US-C1 | 3 分钟内完成资料→绑定→下单 | §1.1 无死路，每步有下一步 |
| US-C2 | 上传截图就能自动填好，一图多件能分开下单 | 三来源可用；失败可手填；拆单每件可核对/排除/分别选类型 |
| US-C3 | 随时知道订单到哪、还要多久 | 七状态+进度条+服务端时间戳 |
| US-C4 | 接单前能取消、送达后能确认 | 动作按 §5.4 出现 |
| US-C5 | 输错或换兼职能重新绑定 | 用完整 `partnerNo` 绑定；换绑仅限无进行中订单；解绑有原因与通知 |
| US-C6 | 兼职失联/订单异常/数据问题都有出路 | 异常可见、可留言、按规则取消；编号可见可复制；删除/注销可用 |
| US-C7 | 全程不涉及任何金钱 | 确认页/帮助页声明可见；界面无任何金钱信息 |
### 1.4 顾客端明确不做
搜索/浏览兼职（CONTRACT §10）；代客单认领（MVP）；评分评价（P2）；地图；原生客服 IM；多兼职/多校区；自建站点（P1）；**任何金钱交易/记账/分摊**（CONTRACT §0 用户硬口径）。


### 2.3 入口参数与落地
| 参数 | 来源 | 校验 | 失败落点 |
| :-- | :-- | :-- | :-- |
| `?bind=partnerNo` | 兼职分享卡片 | 登录后校验完整编号（容错去空格/连字符/全角、转大写，**前缀 P 必填**）；`bind.create` 校验存在/ACTIVE/限流；资料不完整先引导 profile | 格式错/错前缀→bind 页专项提示；不存在/停用/注销→对应错误态 |
| `?orderNo=YYY` | 订阅消息/消息中心/分享 | `order.get` 校验 `customerOpenid`=当前且 `source='CUSTOMER'` | 不存在/越权→订单列表+toast |
| `?reorder=orderNo` | 详情「再次下单」 | 归属校验；只预填服务类型/站点，不复制码/截图 | 失败→普通下单 |
| `?from=` | 卡片/消息 | 仅返回落点标记 | 忽略 |
### 2.4 导航与返回规则
1. tab 间 `wx.switchTab`；跨角色 `wx.reLaunch`；tab 页不接业务参数，业务参数用 `reLaunch` 到分包页。
2. 分包页 `navigateTo`/`navigateBack`；`order-create` 有未提交内容时返回拦截并二次确认（§3.7）。
3. 订单详情默认 `navigateBack`；深链（栈仅 1 层）→ `reLaunch` 订单列表。
4. 绑定卡片：已登录+资料完整→bind 页；未登录→登录后 role/bind；资料未完成→profile 后自动续跳（`pendingBind` 仅内存）。
5. 角色不匹配：tab 页 `onShow` 守卫 `reLaunch` role；未登录/身份失效返回 `FORBIDDEN`（无独立 UNAUTHENTICATED 码）→清内存态→launch。**自定义 tabBar 组件在项目根目录 `custom-tab-bar/`**（平台硬要求）：顾客三格=首页/订单/我的；订单格显示进行中数量角标、我的格显示未读消息红点，进对应页清零。
6. **切换会话（v0.9）**：`READONLY` 顶部黄条 + 写控件置灰/隐藏（服务端拒写）；`TEST_WRITE` 顶部蓝条 + 右上角 `TEST` 角标 + 隐藏分享/转发（写操作只写测试数据）；两种会话退出均回「切换账号」页（`pkg-admin/pages/account-switch/index`）；**小程序不能切换微信登录账号**（CONTRACT §1.3）。
### 2.5 数据可见性硬约束
- 顾客列表/详情**只显示自己 openid 下、`source='CUSTOMER'` 的订单**；代客单 MVP 完全不可见、**不做认领入口**。
- 顾客只能看绑定兼职公开资料（**头像/昵称**/兼职编号/服务类型/接单状态/服务范围）；**解绑/停用/注销后不再返回对方头像/昵称**；看不到 `partnerNote`、其他顾客、其他兼职。
- 头像/昵称仅随**当前 ACTIVE 绑定关系**下发（顾客见绑定兼职、兼职见绑定顾客）；分享卡片只带编号，不含头像/昵称；后台不展示头像、昵称脱敏；订单快照不复制头像/昵称。
- 顾客编号仅本人、绑定兼职、开发者可见；**永无搜索/枚举其他顾客或兼职的接口**。

### 3.6 `pkg-customer/pages/bind/index` 绑定兼职
**目标**：输入完整 `partnerNo`→预览→确认绑定；承载卡片落地与换绑。**前提：资料完整**（不完整先引导去 profile）。
**线框**：
```
绑定兼职
[ 输入完整兼职编号，如 P-7K2-M9X        ] [粘贴]
[查询]
预览卡：小王 · 兼职编号 P-7K2-M9X · 接单中
        服务类型：标准代取 / 送寝上门   服务范围：D 区
        [ 确认绑定 ]
每日最多尝试 5 次 · 如何获取兼职编号？
```
**组件**：编号输入（自动去空格/连字符/全角、转大写、过滤非法字符）、粘贴、查询、预览卡（昵称+编号+服务类型+接单状态+服务范围；**绑定前不显示头像**）、确认绑定、限流说明；换绑模式显示当前绑定。
**五态**：加载=按钮 loading；默认=输入框+说明；空=未输入（确认置灰）；错误=§6.2 场景文案；无权限=未登录→launch；已绑未解绑→「先解绑后才能换绑」。
**交互/校验**：
- 输入 **完整兼职编号**：容错（空格/连字符/全角）+自动转大写，**前缀 P 必填**；合法形态 `^P[23456789ABCDEFGHJKLMNPQRSTUVWXYZ]{6}$`（去分隔后）。
- 错前缀专项：输入 `C…`→「这是顾客编号，请向兼职索取 P 开头的兼职编号」；输入 `DEV…`→「这是开发者编号，不能用于绑定」；其他格式→「兼职编号是 P 开头、共 6 位字母数字，请核对」。
- 300ms 防抖自动查询；预览走 `partner.getPublic({partnerNo})`（未绑定/预备绑定可调、限流 5 次/日/顾客、只返回公开字段）。
- **预览/绑定确认页展示兼职昵称 + 编号 + 服务类型 + 服务范围 + 接单状态**；**绑定前不显示头像**（`bind.getCurrent` 成功后才在首页绑定卡/订单详情展示头像）；`bind.create` 成功返回并展示 `roomTag`。资料不完整→拦截并跳 profile。
- **自绑禁止（v0.9）**：同一微信号既是顾客又是兼职时，**不能绑定自己的兼职账号**（服务端 `FORBIDDEN`，提示「不能绑定自己的兼职账号」）。
- **头像缓存（v0.9）**：首页/详情 `onShow` 重新拉取；换头像后旧 fileId 失效回默认头像；解绑/停用/注销后不再展示对方头像/昵称（页面按 §0.2 口径提示）；本人设备已缓存副本无法技术撤回（仅隐私文本说明，页面不提示）。
- **头像加载**：头像缺失、加载失败、旧 fileId 失效一律默认头像（昵称首字色块），不出现裂图。
- **绑定方向（v0.9）**：绑定只能顾客发起（本页是唯一入口）；兼职端无「添加顾客/绑定顾客/导入顾客/扫码绑定」入口，代客单不产生绑定（CONTRACT §4.2/D20）。
- **测试账号隔离（v0.9）**：测试兼职 `partner.getPublic` 返回 `NOT_FOUND`；真实顾客不能绑定测试兼职（`FORBIDDEN`「测试账号与真实账号不能互相绑定」）；测试账号只能与测试账号互绑（§10）。

## 4. 下单主流程（实现级）
### 4.1 图片来源矩阵（相册/聊天/拍照）
| 来源 | 接口 | 隐私类型（指引需覆盖） | 入口 | 失败落点 |
| :-- | :-- | :-- | :-- | :-- |
| 相册 | `wx.chooseMedia`（album，count:1） | 相册（仅上传） | Step1「从相册选择」 | Step1 错误区 |
| 拍照 | `wx.chooseMedia`（camera，count:1） | 摄像头 | Step1「拍照」 | Step1 错误区 |
| 聊天文件 | `wx.chooseMessageFile`（type image，count:1） | 文件选择（系统选择器） | Step1「从聊天选择」 | Step1 错误区 |
- 均用户主动点击后触发；取消不报错；隐私指引覆盖相册/摄像头/文件选择三类（上线前按微信后台隐私接口清单逐项核对，**隐私文本定稿时复核**）；不做多选/多图合并订单。
### 4.2 压缩与上传时序（CONTRACT §4.1/§4.2）
```
选图成功 → 本地校验（jpg/png；原图 ≤10MB）→ 压缩（canvas 长边 ≤1440、质量 80；循环至 ≤500KB，≤3 次）
 → upload.prepare（客户端生成 draftId → 校身份/配额 → ticket 5 分钟 + cloudPath）→ wx.cloud.uploadFile → fileId → 进入 OCR
```
- `upload_tickets{ticket,openid,cloudPath,draftId,expiresAt,usedAt}` **一次性/可重试**：上传中断→同一 ticket 内重试上传（5 分钟内不重复扣票）；下单创建失败→同一 `draftId`/ticket 重试，不重复扣票；ticket 过期→重新 `upload.prepare`；换图/放弃时调 `upload.cancel` 释放票据。截图云存储路径统一 `orders/{ticket}/image.jpg`（ticket 为不可猜随机串，不用 orderId）。
- `fileId` 写入订单；查看走 `order.imageUrl`（5 分钟临时 URL）；清理按引用计数（拆单共用 `fileId`）。
- 文案：上传失败「截图上传失败：{reason}。可以直接重试（不用重新压缩）。」；票过期「上传凭证已过期，正在重新准备…」。
### 4.3 OCR 进度与失败阶梯（v0.7→v0.8 升级：新增 AI 兜底与失败复核；v3 结论保留）
| 阶段 | 呈现 | 失败码→顾客文案→出路 |
| :-- | :-- | :-- |
| 解码/画帧 | 「正在识别…」 | `IMAGE_DECODE_FAILED`→「这张图没能读出来（可能格式不支持）。换一张图，或手动填写。」→重试/换图/手填 |
| 引擎初始化 | >3s「识别较慢，请稍候」 | `VK_INIT_FAILED`→「识别服务暂时不可用（可能未开通摄像头权限）。手动填写不影响下单。」→手填 |
| 设备不支持 | — | `VK_UNSUPPORTED`→「这台手机不支持自动识别。手动填写不影响下单。」→手填 |
| 无文字 | 「没认出文字」+原文折叠 | `NO_TEXT`→「这张图里没认出取件码。可以手动填写，或先提交让兼职帮你核对。」→手填/换图 |
| 解析 | 字段预填 | 半成品按「只填空格+形态闸」回填；无码有尾号→`NEED_CODE`；都无→手填 |
| 超时 | 单张 OCR ≤40s（v3 阶梯预算） | 「识别时间有点久，换一张更清晰的图，或手动填写。」 |
- 任何失败**不阻断下单**（手填可提交，`NEED_CODE` 允许提交）；自动仅重试解码路 1 次，其余交给用户按钮。
#### 4.3.1 四段阶梯与 AI 兜底五态（v0.8，CONTRACT §4.3/D16）
| 段 | 顾客看到 | 可操作/说明 |
| :-- | :-- | :-- |
| ① 端侧 OCR（v3 阶梯） | 「正在识别…」进度 | 失败按失败码降级，不阻断；手填始终可用 |
| ② 规则解析 | 「识别完成」/半成品预填 | 站点或取件码缺失/不可信（`NEED_CODE`/`stationId=''`/冲突）才触发 AI 兜底 |
| ③ AI 兜底中（≤8s） | 「正在智能识别…」+「取消」+「先手动填写」 | 不阻塞手填；人取消/超时即静默降级；客户端不直连第三方 |
| ④ 兜底成功（HIGH/MEDIUM） | 只填**空字段**（手填优先、不覆盖）；标注「智能识别建议，请核对」 | 仍需人核对后提交；`NEED_CODE` 机制不变 |
| ⑤ 低置信/失败（LOW/LLM_ERROR/解析失败） | 静默降级：「没识别出来，已反馈开发者复核，可手动填写」 | 不弹错误码、不阻断；失败记录进入开发者复核队列 |
**AI 兜底五态**（加载中/成功/低置信/超时/超限静默）：

| AI 兜底态 | 触发 | 顾客看到 | 行为 |
| :-- | :-- | :-- | :-- |
| 加载中 | 兜底请求已发出 | 「正在智能识别…」+「取消」+「先手动填写」 | ≤8s；可取消；手填不阻塞 |
| 成功 | `recognized=true` 且 HIGH/MEDIUM | 「智能识别建议，请核对」 | 只填**空字段**；手填优先不覆盖 |
| 低置信 | `confidence=LOW` | 静默降级：「识别结果不太确定，没自动填。」 | 入复核队列；提示已反馈开发者 |
| 超时 | >8s 或 `LLM_ERROR` | 「智能识别超时，已反馈开发者复核，可手动填写或换一张图。」 | 静默降级；手填/换图 |
| 超限静默 | 5 次/人/日、全局配额用尽或开关关闭 | 与「关闭」同句，**不提示配额** | 不调用、不报错、不返回 `RATE_LIMITED` |

- **aiFallback 三态文案**：关闭（不调用）＝「没识别出来，已反馈开发者复核，可手动填写。」；超时（>8s）＝「智能识别超时，已反馈开发者复核，可手动填写或换一张图。」；超限（5 次/人/日或全局配额）＝与关闭同句、**不提示配额**、不返回 `RATE_LIMITED`；用户主动取消＝「已取消智能识别，可以手动填写。」
- **多码拆单逐条预填**：每件独立识别/兜底，AI 建议只填**该件空字段**，不串件、不覆盖已手填；某件兜底失败只降级该件，其余件不受影响。
- **隐私最小化**：外发仅 `ocrTextMasked`（≤2000 字、手机号/证件号/长数字掩码）+ `hintTrackingTail` + `role`；不发原图/openid/归属；Key 只在云函数环境变量（CONTRACT §4.3/§11.1）。
#### 4.3.2 失败码与顾客文案（v0.8，CONTRACT §4.3）
| `failureCode` | 顾客文案（说真话） | 下一步 |
| :-- | :-- | :-- |
| `NO_TEXT` | 「这张图里没认出文字。」 | 换一张更清晰的图，或手动填写；可先提交让兼职核对 |
| `PARSE_MISS` | 「认出了文字，但没找到站点或取件码。」 | 手动补站点/码，或填运单后 5 位提交（需查明） |
| `LOW_CONFIDENCE` | 「识别结果不太确定，没自动填。」 | 核对识别原文后手动填写；不覆盖已填 |
| `LLM_ERROR` | 「智能识别暂时不可用，已反馈开发者复核。」 | 手动填写，不影响提交；无需等待重试 |
| `IMAGE_UNREADABLE` | 「这张图打不开或压缩失败。」 | 换一张 jpg/png 图，或手动填写 |
- 失败码只用于内部复核队列与文案映射，**不新增业务错误码**；`ai.parseParcel` 失败/超限一律降级为 `recognized=false`（不弹错误、不阻断）。
### 4.4 多码识别与拆单/多图逐张下单
- 一张图识别 N 个码/尾号件 = N 个订单草稿，共享同一 `image.fileId`；每件独立 `stationId/stationName`、`pickupCode`、`lockerNo`、`trackingTail`、`codeStatus`、服务类型、预约、备注。
- 默认全选；可取消勾选「不是我的件」；可手动加一件；提交：单件 `order.create`；一图多码拆单 `order.createBatch`（服务端**原子创建 N 单**，≤5 单，要么全成要么全不建）。
- **多张截图分别下单**：一次只处理 1 张图；提交流程结束后回首页再传下一张（不做队列合单）。
### 4.5 字段确认与形态闸
| 字段 | 来源 | 校验 | 空值语义 | 错误文案 |
| :-- | :-- | :-- | :-- | :-- |
| `stationId/stationName` | 识别/手选 | 必须命中 P1~P8 正式名，不做自建 | 不允许空 | 「请选择去哪取（按驿站站点）」 |
| `pickupCode` | 识别/手填 | ≤40+v3 形态闸 | `''`→需 `NEED_CODE` 支路 | 「这串不太像取件码，请核对」 |
| `lockerNo` | 识别/输入 | **≤10 字符串；值域不限定**（如「7号柜」） | `''`=未知（合法） | 「柜号最多 10 个字」 |
| `trackingTail` | 识别/手填 | 恰好 5 位数字；有码时为空 | `''`=不适用 | 「运单后 5 位要正好 5 位数字」 |
| `codeStatus` | 派生 | 有码→`OK`；无码有尾号→`NEED_CODE`；都无→不可提交 | — | 「还没有取件码：可手动填写，或填运单后 5 位先提交」 |
- 只填空格：识别不覆盖手改值；「重新识别」需确认清空。
### 4.6 服务类型选择（CONTRACT §6：只有类型名称与说明）
| `serviceCode` | 名称 | 说明（只描述做什么） |
| :-- | :-- | :-- |
| `PICKUP_STD` | 标准代取 | 驿站取件送到宿舍楼下/约定地点 |
| `PICKUP_DOOR` | 送寝上门 | 送到寝室门口（上楼） |
| `PICKUP_URGENT` | 加急代取 | 优先处理，承诺更快时效 |
| `DROP_OFF` | 代寄快递 | 顾客把件交给兼职，兼职送驿站寄出 |
| `CUSTOM` | 其他代办 | 需备注说明；兼职可拒单 |
- 只展示兼职已启用服务类型（`partner.serviceConfig.services`；范围先到苑级 `zones`）；订单只快照 `service{code,name}`；**无任何金钱信息**。
- 全部服务类型选择控件只显示名称+说明；`CUSTOM` 强制备注；MVP 不存在加价项概念。
### 4.7 预约与备注
- `appoint.type=ASAP`：默认。
- `appoint.type=SLOT`：MVP 六时段「今天/明天 × 上午 08:00-12:00 / 下午 12:00-18:00 / 晚上 18:00-22:00」；`startAt/endAt` 必填；服务端按 `serverTime` 校验未来，过期/无效返回 `VALIDATION_FAILED`→红字。
- 拆单每件独立预约（默认继承第一件）；`note` ≤200 字（CONTRACT §5.2）；可空；提示禁止码/手机号；MVP 不做送达照片/签名。
### 4.8 提交幂等与失败重试
1. 每件在进入 Step4 生成 `clientRequestId`（16~32 位）；服务端创建幂等 `requestKey={customerId}:{clientRequestId}`（拆单每条后缀 `:{itemIndex}`）。
2. 按钮点击立即 loading+禁用；页面级 `submitting` 锁。
3. 超时/结果不确定：**不换 id**，同一 `clientRequestId` 重试（幂等成功返回同一订单）；并发/版本冲突返回 `CONFLICT`。
4. 拆单走 `order.createBatch`（原子，≤5 单）；失败保留草稿可重试；内容修改后重新生成 `clientRequestId`。
5. 顾客取消/确认等写动作同样带 `clientRequestId`（`order_events.requestKey={orderId}:{action}:{clientRequestId}`）。
### 4.9 提交结果（内嵌第 4 步）
- 结果**内嵌在 `order-create` 第 4 步结果块**，不新增 `result` 子页。
- 单件成功：`redirectTo` 订单详情 `?orderNo=`，toast「已提交，等待兼职接单」。
- 拆单（`order.createBatch`）成功：结果块列出 N 张订单号 + 每张「查看订单」入口 +「回首页」，不自动跳转；失败停留 Step4，错误条+「重试」，内容不丢（原子创建，不产生半完成订单）。
### 4.10 头像与昵称采集（v0.9，CONTRACT §4.1/§4.2/D19）
- **采集方式**：头像用 `button open-type="chooseAvatar"`（微信头像选择器），昵称用 `input type="nickname"`（微信昵称一键填入、可改/手填）；**均用户主动点击后触发**，不自动读取。
- **昵称**：**必填 ≤20 字**，可改/手填，保存过 `security.msgSecCheck` v2；未填不能完成资料（阻断保存并提示「昵称不能为空」）。
- **头像**：**可拒绝/跳过→默认头像**（昵称首字色块），不阻断资料完成与下单；jpg/png、**≤200KB**、建议 200×200；**不采集相册里的其他照片**。
- **上传**：`upload.prepare({purpose:'AVATAR'})` → `avatars/{role}/{random}.jpg`；替换即删旧文件；失败保留旧头像/默认头像并提示重试（头像上传 5 次/日/人）。
- **展示与可见范围**：**绑定前预览只回昵称+编号+服务/范围/接单状态，不显示头像**；只随当前 **ACTIVE 绑定关系**下发给对方（`bind.getCurrent` 成功后首页绑定卡/订单详情展示头像）；本人在「我的」可编辑；分享卡片/通知/后台/日志不含头像与完整昵称；`onShow` 重新拉取，换头像后旧 fileId 失效回默认头像；解绑/停用/注销后不再展示对方头像/昵称（文案「对方已解除绑定，头像/昵称不再展示」）；本人设备已缓存副本无法技术撤回（仅隐私文本说明，页面不提示）。
- **注销/删除测试账号**：随账号删除头像文件（§9.4）；代客单 guest 无微信资料 → 展示默认头像 +「代客单」标签。

## 5. 订单进度展示矩阵（七状态）
### 5.1 七状态 × 顾客展示矩阵
| `status` | 顾客标题 | 说明文案 | 进度节点 | 顾客动作 | 取消性 | 时间字段 |
| :-- | :-- | :-- | :-- | :-- | :-- | :-- |
| `SUBMITTED` | 待接单 | 已提交，等待兼职接单 | ①下单（当前） | 取消；留言 | ✅ 可取消 | `statusUpdatedAt` |
| `ACCEPTED` | 已接单 | 兼职已接单，正在安排取件 | ②已接单（当前） | 取消（未取件前）；留言 | ✅ 可取消 | `acceptedAt` |
| `PICKED` | 已取件·配送中 | 兼职已取到快递，正在送来 | ③已取件（当前） | 留言；等异常处理 | ❌ 不可直接取消 | `pickedAt` |
| `DELIVERED` | 已送达·待确认 | 兼职已送达，请确认收到 | ④已送达（当前） | 确认送达；留言 | ❌ | `deliveredAt` |
| `COMPLETED` | 已完成 | 订单已完成 | ⑤已完成 | 删除记录；再次下单；留言只读 | — | `completedAt` |
| `CANCELLED` | 已取消 | 订单已取消：{cancelReason} | 进度条置灰+取消分支 | 再次下单；查看原因 | 终态 | `cancelledAt` |
| `EXCEPTION` | 异常·待处理 | {exception.text}（兼职正在处理） | 当前节点标红+异常分支 | 留言；按 §5.4 取消 | ⚠️ 见 §5.4 | `statusUpdatedAt` |
### 5.2 进度条与分支
```
正常：①下单 ─ ②已接单 ─ ③已取件 ─ ④已送达 ─ ⑤已完成
取消/异常：取消=置灰+显示原因；异常=当前节点标红+exception.text，恢复回 fromStatus 或转已取消
```
节点状态：已完成（实心+对勾）/当前（高亮+呼吸点）/未来（空心灰）/异常（红+!）/取消（灰+✕）；只由服务端 `status`/`order_events` 决定。
### 5.3 时间展示
- 相对时间：`刚刚`（<1 分钟）/`{n} 分钟前`（<1 小时）/`{HH:mm}`（今天）/`昨天 {HH:mm}`/`{MM-DD} {HH:mm}`；基准 `serverTime`。
- 列表排序（CONTRACT §5.2 定稿，服务端排序、客户端不二次排序）：进行中按 `statusUpdatedAt desc`；已完成/已取消按 `completedAt`/`cancelledAt desc`；分页游标 `(statusUpdatedAt, orderNo)` 或 `(completedAt, orderNo)`。
- 时间线至少展示：下单/接单/取件/送达/完成/取消/异常（含回退事件 §5.5）；`NEED_CODE` 补码显示「兼职已补齐取件码」。
- 时间线事件类型（`order_events.type`）：`ORDER_CREATED/ACCEPTED/PICKED/PICKED_REVERTED/DELIVERED/DELIVERED_REVERTED/COMPLETED/AUTO_COMPLETED/CANCELLED/TIMEOUT_CANCELLED/EXCEPTION_REPORTED/EXCEPTION_RESOLVED/ORDER_CORRECTED/DELETED_BY_CUSTOMER`；`actorRole∈{CUSTOMER,PARTNER,ADMIN,SYSTEM}`。
### 5.4 顾客动作 × 状态矩阵
| 动作 | SUBMITTED | ACCEPTED | PICKED | DELIVERED | COMPLETED | CANCELLED | EXCEPTION |
| :-- | :-: | :-: | :-: | :-: | :-: | :-: | :-: |
| 查看进度/时间线/截图 | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ |
| 留言 | ✅ | ✅ | ✅ | ✅ | ❌（只读归档） | ❌ | ✅ |
| 取消订单（`order.cancel`） | ✅ | ✅ | ❌ | ❌ | ❌ | ❌ | ⚠️ `fromStatus∈{SUBMITTED,ACCEPTED}` 可取消；`PICKED/DELIVERED` 不可单方取消 |
| 确认送达（`order.confirmDelivery`） | ❌ | ❌ | ❌ | ✅ | ❌ | ❌ | ❌ |
| 删除记录（`order.deleteRecord`） | ❌ | ❌ | ❌ | ❌ | ✅（软删） | ❌ | ❌ |
| 再次下单 | ❌ | ❌ | ❌ | ❌ | ✅ | ✅ | ❌ |
### 5.5 状态回退与纠正提示（CONTRACT §5.1）
- `PICKED_REVERTED`（`order.unmarkPicked`）：进度回退到「已接单」；顶部提示「兼职更正了取件状态：已退回「已取件」。」；时间线展示事件；顾客动作恢复可取消（未取件）。
- `DELIVERED_REVERTED`（`order.unmarkDelivered`）：进度回退到「已取件·配送中」；提示「兼职更正了送达状态：订单回到配送中。」；「确认已收到」消失。
- `ORDER_CORRECTED`（`order.correct`，不改归属）：显示「兼职更正了订单信息（{字段}）」+变更后字段，不显示旧值明文（L3）。
- `EXCEPTION_RESOLVED`（`order.resolveException`）：提示「异常已解除，订单继续处理」；进度回 `exception.fromStatus`。
- 回退不是错误：只按服务端 `status` 重绘，保留已读消息与留言。
### 5.6 异常码显示映射（`exception.code`）
| `code` | 顾客端标题+摘要（正文以 `exception.text` 为准） | 顾客可做 |
| :-- | :-- | :-- |
| `CODE_INVALID` | 异常·取件码无效：「兼职反馈取件码/柜号无效或已被取走，正在处理。」 | 留言；按 §5.4 取消 |
| `PARCEL_NOT_FOUND` | 异常·驿站找不到件：「兼职在驿站没找到这件快递，正在核对。」 | 留言；按 §5.4 取消 |
| `CABINET_ERROR` | 异常·快递柜故障：「快递柜打不开或设备故障，兼职正在处理。」 | 留言；按 §5.4 取消 |
| `CUSTOMER_UNREACHABLE` | 异常·联系不上你：「兼职联系不上你，请尽快留言或回电。」 | 留言；按 §5.4 取消 |
| `ADDRESS_ISSUE` | 异常·地址有问题：「宿舍地址需要确认，请留言告诉兼职准确位置。」 | 留言；按 §5.4 取消 |
| `OTHER` | 异常·其他：`exception.text`（必填备注），前端不拼 | 留言；按 §5.4 取消 |
### 5.7 超时与自动完成
- `SUBMITTED`：「等待接单 {mm:ss}（超过 {orderTimeoutMinutes} 分钟将自动取消）」，<10 分钟警告色；超时→`CANCELLED`（原因「超时未接单」）。
- `DELIVERED`：「送达 {autoCompleteHours} 小时后未操作将自动完成」；系统完成 actor=SYSTEM。
- 倒计时以 `serverTime` 对齐，禁止本机时钟偏差。

## 6. 绑定与被绑全场景
### 6.1 绑定路径
1. 输入/粘贴：bind 页手输**完整兼职编号**（容错去空格/连字符/全角、转大写；前缀 P 必填）→查询预览→`bind.create`。
2. 卡片落地：兼职分享卡片 `?bind=partnerNo`→launch→role/bind→自动带编号→预览→确认（免输入）。
3. 换绑/解绑：profile/bind?mode=rebind；**前提=资料完整且无进行中订单**；换绑成功后新 `ACTIVE`、旧 `RELEASED`（`releaseReason=CUSTOMER_INITIATED`）、`roomTag` 重分配；解绑走 `bind.release`（`reason` 必填枚举 + 可选 `note` ≤100 字），有进行中订单禁止解绑/换绑。
4. **绑定方向（v0.9）**：**只能顾客发起绑定**（本页/卡片落地是唯一入口）；兼职端无任何「添加/绑定/导入顾客」入口，代客单不产生绑定；解绑后双方**不再互见头像/昵称**（CONTRACT §4.2/D20）。
### 6.2 场景矩阵
| 场景 | 触发 | 顾客可见反馈 | 可执行 |
| :-- | :-- | :-- | :-- |
| 资料不完整 | 进入绑定/卡片落地 | 「先完善苑/楼栋/宿舍号才能绑定。去完善」 | 跳 profile 顾客视图 |
| 测试兼职 | 绑定测试账号的 `partnerNo` | 「该兼职是测试账号，真实账号不能绑定。」（`FORBIDDEN`/`NOT_FOUND`） | 改编号 |
| 自绑 | 同一微信号既顾客又兼职，绑定自己的 `partnerNo` | 「不能绑定自己的兼职账号」（`FORBIDDEN`） | 改绑定其他兼职 |
| 解绑后 | 绑定已释放 | 首页/订单不再展示对方头像与昵称；显示「对方已解除绑定，头像/昵称不再展示」 | 重新绑定 |
| 空输入 | 未填编号 | 「请输入兼职编号后再查询」 | 输入 |
| 错前缀-顾客 | 输入 `C…` | 「这是顾客编号，请向兼职索取 P 开头的兼职编号」 | 改输入 |
| 错前缀-开发者 | 输入 `DEV…` | 「这是开发者编号，不能用于绑定」 | 改输入 |
| 格式错 | 去分隔后非 `P`+6 位字母表 | 「兼职编号是 P 开头、共 6 位字母数字，请核对」 | 改输入 |
| 粘贴 | 剪贴板含完整编号 | toast「已粘贴」+自动查询 | 确认绑定 |
| 不存在 | `NOT_FOUND` | 「没有找到这个兼职编号，请向兼职本人确认。」 | 改输入 |
| 停用 | `partners.status=SUSPENDED` | 「这位兼职已停用，暂时不能绑定。」 | 换绑 |
| 注销 | `partners.status=CLOSED` | 「这位兼职已注销，不能绑定。」 | 换绑 |
| 已绑自己 | `CONFLICT` | 「你已经绑定这位兼职了。」 | 回首页 |
| 已绑他人 | 已有 ACTIVE | 「你当前已绑定另一位兼职，请先解绑或换绑。」 | 换绑/解绑（`bind.release`） |
| 顾客解绑 | `bind.release`（`reason` 必填枚举+可选 `note`≤100；需无进行中订单） | 二次确认后 toast「已解绑，历史订单仍保留」 | 回首页 |
| 换绑/解绑挡住 | 有进行中订单 | 「你还有进行中的订单，完成或取消后才能换绑/解绑。」 | 去订单 |
| 换绑成功 | 无进行中订单+新编号 | toast「已换绑为「{displayName}」」 | 回首页 |
| 兼职解绑 | `bind.release`/`partner.unbindCustomer`（`reason` 必填枚举+可选 `note`≤100） | 消息「兼职「{displayName}」已解除绑定，原因：{原因}。」 | 去绑定 |
| 兼职注销释放 | `PARTNER_CLOSED` | 「兼职已注销，绑定已解除；进行中订单由平台处理（异常/完成）。」 | 换绑 |
| 限流 | `counters.rl:bind:*` 超限 | 「今天尝试绑定次数已用完（每天 5 次），请明天再试。」 | 明天再试 |
- `releaseReason` 文案：`CUSTOMER_INITIATED`「你主动解绑」；`PARTNER_INITIATED`「兼职解除」；`PARTNER_CLOSED`「兼职注销」；`ADMIN_ACTION`「平台处理」；`CUSTOMER_ACCOUNT_CLOSED`「账号注销」。
- 解绑后历史订单保留、详情只读；`roomTag` 不再展示新分配值。
### 6.3 绑定卡片（分享）
- 内容：兼职 `displayName`、`partnerNo`（可复制）、服务类型摘要（≤2 项）、「绑定后即可下单」；**不含**顾客数据/订单/openid/宿舍/尾号/昵称/**头像**/`partnerNote`。
- 路径 `/?bind={partnerNo}&from=card`；登录态正确则直达 bind 预览；预览走 `partner.getPublic({partnerNo})`（未绑定可调、限流 5 次/日/顾客、只返回公开字段）；无「搜索/浏览兼职」入口，`partnerNo` 不可枚举。

## 7. 资料表单（`pages/profile/index` 顾客视图内）
### 7.1 字段与校验
| 字段 | 控件 | 校验 | 必填 | 错误文案 |
| :-- | :-- | :-- | :-: | :-- |
| `customerNo` | 只读（由服务端生成） | `^C[23456789ABCDEFGHJKLMNPQRSTUVWXYZ]{8}$`，仅展示/复制 | — | — |
| `zone` | picker（D→X→N→B→C） | 枚举内 | ✅ | 「请选择苑/楼区」 |
| `buildingNo` | picker 1~10 | 整数 1~10 | ✅ | 「请选择楼栋号（1~10）」 |
| `room` | 数字输入 | ≥100；前导零归一（`0522`→`522`） | ✅ | 「宿舍号要填 3 位以上数字（如 522）」 |
| `dormKey` | 只读 | `zone+buildingNo+'-'+room` | — | — |
| `phoneTail` | 数字输入 | `''` 或恰好 4 位 | ❌ | 「手机尾号写后 4 位数字，不知道就留空」 |
| `displayName` | 输入 `type=nickname`（一键填入微信昵称） | **必填**、≤20 字、可改/手填；**输入即截断+toast**；过 `msgSecCheck` v2 | ✅ | 「昵称不能为空」/「昵称最多 20 个字，已截断」 |
| `avatarFileId` | `chooseAvatar` | 可空（拒绝/跳过→默认头像）；jpg/png、≤200KB、建议 200×200；替换删旧 | ❌ | 「头像上传失败，可重试或先用默认头像」 |
### 7.2 交互
- 苑/楼栋 picker（不可手输）；宿舍号数字键盘；实时预览「你的宿舍：{dormKey}」。
- `phoneTail` 4 位数字键盘，占位「后 4 位，可不填（仅用于同寝室区分）」；`displayName` 用 `input type=nickname` 一键填入微信昵称，**必填**、≤20 字、可改/手填（**输入即截断并 toast「昵称最多 20 个字，已截断」**，不做超长报错；保存时仍过服务端 `msgSecCheck`）；`avatarFileId` 用 `chooseAvatar` 选择，可「使用默认头像」/跳过，头像与昵称成对展示。
- 头像不采集相册其他照片；头像上传失败/拒绝不影响资料完成与下单（默认头像兜底）；替换头像即删旧文件。
- 资料编辑：昵称/头像/可选手机尾号可随时改；**宿舍身份（苑/楼栋/宿舍号）仅在无进行中订单时可改**（否则服务端 `INVALID_STATE`，提示先完成/取消）。保存走 `customer.saveProfile`（首次保存生成 `customerNo`，幂等）；提示「保存后新订单将使用这份资料，已提交的订单不受影响。」；成功 toast「资料已保存」；失败「资料保存失败：{reason}，请重试」。
- `customerNo` 首次生成后不可修改；不作为登录/绑定凭据。
### 7.3 `roomTag` 与唯一编号说明
- **资料完整是绑定前提**；`roomTag` 在**绑定成功时**分配（作用域=兼职+dormKey）；未绑定不分配。
- 「资料保存成功」**不显示也不承诺同寝室标识**；绑定成功后才在 `pages/profile/index` 顾客视图资料卡显示「同寝室标识：D4-522A」（**恒大写 A…Z/AA…**，Excel 列名式；排序按 `dormKey + roomTag` 大写字母序 = 绑定顺序，历史 tag 不复用）。
- 已绑定期间改宿舍（dormKey 变化）：**禁止原地改 `bindings.dormSnapshot`**；须旧 binding `RELEASED` → 新建 binding，并在新 dormKey 下重新分配 `roomTag`（旧 tag 不复用，允许空洞）；有进行中订单时先拦截（见 §7.4）。顾客不可编辑 `roomTag`。
- `customerNo` 用于识别/客服（展示/复制）；`partnerNo` 用于绑定对方；两者都不是登录凭据。
### 7.4 编辑资料对订单的影响
| 场景 | 影响 |
| :-- | :-- |
| 改 `displayName`（昵称）/`phoneTail`/头像 | 新订单与绑定对方展示用新值；进行中/历史订单快照不变（订单快照不复制头像/昵称） |
| 改 `zone/buildingNo/room`（`dormKey` 变化） | **有进行中订单禁止改**（`INVALID_STATE`，提示先完成/取消）；无进行中订单时：旧 binding `RELEASED`→新建 binding+新 dormKey 重分配 `roomTag`（禁止原地改 `bindings.dormSnapshot`）；已有订单保留创建时快照 |
| 换绑后 | `roomTag` 重分配；历史订单保留原 `roomTag` 与编号快照 |
| 资料不完整 | 不能绑定、不能下单（入口拦截并引导） |

### 9.4 注销账号（CONTRACT §11.4/§4.2）
```
我的 → 注销账号 → 检查进行中订单（有→阻断并去订单；无→二次确认）
 → `user.deleteAccount`：立即匿名化订单（去 openid/昵称/尾号/宿舍/截图引用，写 anonymizedAt）+ 删截图/留言/绑定/partnerNote + **删头像文件**
 → 写 users.deletionRequestedAt，30 天内物理删除；`customerNo` 作废不再分配
```
- 注销不可撤销；结果页「已注销。订单与资料已匿名化或删除，30 天内完成彻底清理；重新登录将创建新的顾客资料与编号。」
### 9.5 删除单条订单记录
- 仅 `COMPLETED` 可删（动作 `order.deleteRecord` 写 `deletedByCustomerAt` 软删）；**7 天后物理删除（含留言）**，删除后列表/消息不再展示（CONTRACT §5.1）。
- 顾客不能删进行中/已取消订单；兼职与 admin 均不可删订单（CONTRACT §5.1）。
### 9.6 留存告知（三处一致：隐私弹窗/帮助/详情页脚注）
- 截图：终态/取消后 7 天删除；订单信息：终态后 180 天→匿名化（`anonymizedAt`）→再 30 天物理删除；账号注销：立即匿名化+删截图，30 天内物理删除。**所有留存天数从 `config.getPublic` 返回的配置读取（截图/订单/匿名化/自动完成等），页面不写死数字。**
- 识别失败兜底（v0.8）：去敏 OCR 文本外发第三方 AI（不落第三方存储、不用于训练）；失败原图与复核记录默认 30 天（`config.recognitionFailureRetentionDays` 7~30 可配），到期删除；复核页原图临时 URL 5 分钟且每次审计。
- 头像/昵称（v0.9）：头像文件随账号存续，**换头像/注销/删除测试账号即删旧文件**；解绑/停用/注销后不再向对方展示（DTO 按 ACTIVE 绑定关系返回）；分享卡片/通知/日志/后台不含头像与完整昵称；**对方设备已缓存的副本无法技术撤回**（隐私文本说明，页面不提示）。
- 未成年人提示：隐私弹窗与协议含「未成年人需在监护人指导下使用」。

### 11.4 复用规则
- 页面只 `setData`/事件转发；校验、状态映射、编号格式、倒计时放零件层（`utils/order-status.js`、`utils/ids.js`、`utils/error-copy.js` 等，零 `wx`；CONTRACT §12）；编号格式/校验/错前缀提示**单源** `utils/ids.js`，页面不自己拼编号或写死格式。
- 状态文案/颜色/动作可用性**单源** `utils/order-status.js`；页面禁止硬编码中文状态；`custom-tab-bar/` 与组件均从该单源取角色/状态。
- 组件不直调云函数，数据由页面注入，事件 `bind:action` 上抛；共享组件放 `components/`，顾客专用放 `components/customer-*`。
### 11.5 可访问性
- 状态不只靠颜色（颜色+文字/图标双编码）；可点区域 ≥88rpx；正文对比度 ≥4.5:1；编号等宽、独立行；复制按钮有成功反馈。
