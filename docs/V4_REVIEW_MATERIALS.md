## 0. 全文通用口径

- **零金额口径**：本小程序只提供下单、接单与取件信息整理，**不涉及任何金钱交易**；没有支付入口、没有账目字段、没有金钱计算或对账环节；服务类型只表达"做什么"，不承载任何数量或金钱信息。
- 产品名称、简介、截图、审核备注、客服话术统一按上一条表述；任何材料不得暗示本程序具备支付或账目能力。
- 隐私配置以代码与 `config` 当前值为准（`privacyVersion`、留存期限、头像上限等），逐项核对口径见 `docs/privacy/发布前填写清单.md` §3，本文件不另立数字。
- **第三方 AI**：仅截图识别失败时，把**去敏 OCR 文本**发送给 DeepSeek 做辅助识别；**原图不发送第三方、不出本程序云存储**；失败记录进开发者复核队列（`[D16]`/`[D17]`）。
- **头像/昵称**：`chooseAvatar` 采集头像（自愿，可拒绝→默认头像）、`nickname` 输入采集昵称（必填、可改/手填）；仅当前 ACTIVE 绑定关系的对方可见，后台不展示头像、昵称脱敏（`[D19]`）。
- **账号切换**：平台**不能切换微信登录账号**；真实账号**只读**（黄条 + 服务端拒写 + 审计）、测试账号为后台合成账号（蓝条 + `TEST` 角标、只写测试数据、不计统计）（`[D14]`/`[D18]`）。
- D# 编号指向 `docs/V4_CONTRACT.md` §13 的裁决表；未决事项统一在 §7 标"待用户裁决"，不在此处自行拍板。

### 0.1 使用顺序（建议按此四步）

1. 按 §1 逐项准备：任一 P0 项未完成，**不得提审**。
2. 按 §2 在体验版（trial）与提审版本（同一云环境，D1 修订单环境）各走一遍对应路径，全程按 §5 留存证据。
3. 把 §3 模板中的占位符填好（只填占位符），粘进微信公众平台提审页的审核说明/补充材料栏（以后台实际字段为准）。
4. 被驳回时按 §4 对照处理；处理完回到 §1/§5 更新证据。提审通过后执行"审核后清理"（作废审核专用邀请码、清理演示数据），记入 §5 与 `docs/RUNBOOK.md` §13。

## 2. 分角色审核体验路径

> 前置：审核员用自己的微信号进入，无需提供密码；每个账号首次进入先过隐私弹窗（同意前不调用相册/摄像头/头像等隐私接口）。建议顺序：顾客 → 兼职 → 开发者后台演示。括号内为页面路径，便于截图定位。

### 2.1 顾客侧（审核员本人微信号；资料与下单可自助）

1. 打开小程序 → `pages/launch/index`：隐私弹窗先读后同意；点"暂不同意"停在启动页，可再次查看/同意，不反复纠缠（QA P1/P10）。
2. `pages/role/index`：点「我是顾客」进入顾客首页。
3. `pages/profile/index`（顾客视图）：昵称必填（一键取微信昵称或手填，≤20 字）；头像可选（`chooseAvatar`，拒绝后显示默认头像，不阻断）；填苑/楼栋/宿舍号，手机尾号可留空；保存后显示顾客编号 `C-XXXX-XXXX`。
4. `pkg-customer/pages/bind/index`：只能由顾客输入完整兼职编号发起绑定；兼职端没有任何绑定入口（绑定方向 `[D20]`）。若审核员没有可绑定的兼职，见 §2.5。
5. `pkg-customer/pages/order-create/index`（四步同页）：截图（相册/拍照/聊天三来源）→ 识别核对（可手填、多码可拆单）→ 选服务类型与预约 → 确认提交。成功进订单详情。
6. `pkg-customer/pages/order-detail/index`：看进度/事件时间线、双方编号、取消/留言/删除记录；截图走临时链接。**页面没有任何支付或数值记录区域**，底部固定零金额声明。
7. `pages/profile/index` → 消息中心、帮助页（隐私政策/用户协议全文）、账号与注销入口、解绑入口。
8. 注销：`我的 → 账号 → 注销账号`；有进行中订单会被拦截并提示先处理，无进行中可发起（动作按服务端校验，不由前端放行）。

### 2.2 兼职侧（审核员用审核专用邀请码；单机可走完整履约）

1. `pages/role/index` →「我是兼职」→ `pkg-partner/pages/activate/index`：输入审核专用邀请码（12 位，形如 `XXXX-XXXX-XXXX`）、填昵称（必填、可一键取微信昵称）、头像可跳过、勾选协议 → 激活。预期结果块显示兼职编号 `P-XXX-XXX`（可复制），并提示"先配置服务类型再开始接单"。
2. `pkg-partner/pages/service-settings/index`：至少启用一个服务类型、选择苑范围、打开接单开关 → 保存成功。
3. `pages/partner/workbench/index`：空态有首用引导；可「分享绑定卡片」邀请顾客**自己**绑定（兼职端无"添加/绑定顾客"入口）。
4. 单机跑通订单生命周期（无需第二个微信号）：工作台/客户页 → `pkg-partner/pages/create-on-behalf/index` 代客下单（选择"新顾客"guest 路径：填收件人称呼、宿舍、可选尾号，截图或手填，选服务类型，提交）→ 工作台接单 → 批量"已取件" → 送达 → 顾客未确认时按配置自动完成；状态与时间线全程可见。
5. `pkg-partner/pages/order-detail/index`：补码/改站点/异常上报/留言/送达备注；`pkg-partner/pages/customer-detail/index`：顾客资料（仅绑定顾客，头像昵称+编号+备注仅自己可见）。
6. `pkg-partner/pages/stats/index`：只有单量、完成量、状态分布、异常数；**没有任何收入或账目指标**。
7. `pages/profile/index`（兼职视图）：兼职编号、服务配置、单量统计、消息、切换身份。

### 2.3 开发者侧（后台入口 → 真实只读 → 测试可写 → 复核 → 审计）

> 前置说明（审核材料必须如实写明）：后台只对云函数环境变量 `ADMIN_OPENIDS` 白名单内的微信号开放，无自助注册、无二维码/口令入口；**审核员微信号不在白名单，无法自行进入后台**。因此本段默认以运营者的**录屏 + 分步截图**提交；如审核方要求实机体验，按 §7 第 3 项另行安排。

1. 开发者白名单微信号打开小程序 → `pages/launch/index` 由 `user.bootstrap` 的 `isDeveloper=true` 自动分流到 `pkg-admin/pages/overview/index`（无需 `?admin=1`，白名单是唯一门槛）。
2. 总览：统计卡、异常工单、识别失败待复核摘要、审计区块、「切换账号」入口、后台消息。
3. `pkg-admin/pages/account-switch/index` 真实账号 tab：选角色 → 按完整编号搜索或列表选人（仅 ACTIVE）→ 确认卡（只读并审计、有效期、隐藏分享）→ 进入目标首页。预期：顶部黄条 `开发者只读视角 · 顾客 C-… · 退出`；写控件置灰/隐藏；用工具构造写请求返回 `FORBIDDEN`（双保险）。
4. 同页测试账号 tab：新建测试顾客/测试兼职（昵称"测试-…"）→ 选择进入。预期：顶部蓝条 `测试账号 · 顾客 C-…（测试） · 由 DEV-01 切换` + 每页右上角 `TEST` 角标；可正常操作但只写测试数据；退出后真实数据与统计不变（测试数据被 `isTest` 标记并排除统计）。
5. `pkg-admin/pages/recognition-review/index`：造假失败图 → 列表筛 `PENDING` → 查看原图（临时链接短时有效、**每次查看落 `FAILURE_IMAGE_VIEW` 审计**）→ 补录站点/取件码（只回填识别字段，不改订单状态、不代确认、不创建订单）→ 通知上传者/标记忽略（备注必填）；随后在审计中可查 `FAILURE_IMAGE_VIEW`/`FAILURE_FIX`/`FAILURE_IGNORE`。
6. 治理与审计：总览审计区块可查 `ACCOUNT_SWITCH_START/END/EXPIRED`、`TEST_ACCOUNT_*`、`CONFIG_UPDATE`；邀请码生成/作废、兼职停启用、异常介入取消均留审计；配置页只展示可编辑白名单项（`privacyVersion` 不提供页面编辑入口，由部署脚本/后台配置写入）。
7. 退出：黄条/蓝条「退出」→ 回「切换账号」页；切换会话默认按 `config.viewTicketTtlMinutes` 当前值过期（可配 5~60），票据只存客户端内存、不落本地存储；同一开发者同时只有一个会话。

### 2.4 为什么这些路径不涉及交易语义（审核说明可直接引用）

- 服务类型 = 名称 + 说明，没有数量、记录或账目概念；页面、接口返回体、截图、统计中都不含任何金钱字段或支付控件。
- 订单状态机只表达履约进度（提交→接单→取件→送达→完成/异常/取消）；没有"已支付/待支付/已退款"一类状态。
- 统计只有单量、完成率、状态分布与异常数；没有收入、账期或报表指标。
- 没有第三方支付组件与支付回调，没有账目写入；取件码截图只用于识别与兼职核对。
- 因此审核演示不会出现任何支付或对账环节；隐私指引与用户协议使用同一口径。

### 2.5 审核员只有一台手机/一个微信号时怎么办

- 顾客侧可自助走通：隐私弹窗 → 资料（含头像/昵称可拒绝路径）→ 截图识别/手填 → 服务类型 → 无绑定时的绑定引导 → 我的/帮助/隐私全文/注销入口。
- 兼职侧可自助走通完整履约（§2.2 第 4 步的代客下单不需要第二账号）。
- **绑定后的完整顾客下单与进度**需要"可被绑定的真实兼职编号"或录屏：默认用录屏 + 分步截图提交；是否在唯一环境提供主体自有的演示兼职，见 §7 第 2 项待用户裁决。
- 开发者后台受白名单限制，默认用录屏；**不建议**临时把审核员加入白名单（无法预知审核员 openid，且属控制台配置变更，只能用户执行）。

## 3. 审核说明文本模板（可直接粘贴；只填占位符）

> 使用规则：①只替换 `{{…}}` 占位符；②不写真实 openid/appid/Key/内部错误码/实现细节；③附件与 §5 证据表一一对应；④若审核备注字段长度受限，先用"简版"再在补充材料中放完整版与录屏。

```text
【小程序名称】{{对外名称}}｜体验版本 {{版本号}}
【一句话说明】本小程序面向在校学生，提供校园快递代取的下单、接单与取件信息整理；不涉及任何金钱交易，全链路没有支付或账目功能。

【体验方式】
1. 顾客：打开小程序→同意隐私政策→选择「我是顾客」→完善昵称（必填，可一键取微信昵称）与头像（可选，拒绝后显示默认头像）→填宿舍信息→获得顾客编号 C-XXXX-XXXX。绑定兼职需输入完整兼职编号；绑定、下单与进度的完整流程见随附录屏。
2. 兼职：在身份选择页点「我是兼职」→输入本条说明随附的一次性审核体验邀请码 {{审核邀请码}}→填写昵称（头像可选）→配置至少一个服务类型与苑范围→工作台可「代客下单」（新顾客，无需绑定）→接单→已取件→送达，单机即可完成完整履约流程。兼职端不提供绑定顾客入口（绑定只能由顾客发起）。
3. 开发者后台：仅运营者白名单微信号可进入（无自助注册，普通用户无入口）；真实账号只读（黄条 + 服务端拒写 + 审计），测试账号为后台合成账号（蓝条 + TEST 角标，只写测试数据、不计统计）。后台演示见随附录屏与截图。

【隐私与第三方说明】
- 采集微信昵称与头像：头像可拒绝（默认头像），仅当前绑定的对方可见；后台不展示头像、昵称脱敏。
- 取件码截图仅用于识别与兼职核对；识别失败时会把去敏后的文字发给第三方 AI 服务 DeepSeek 做辅助识别，原图不发送给第三方，仅进入开发者复核队列（临时查看、逐次审计、按配置到期删除）。
- 开发者后台默认脱敏；完整数据仅通过只读视角查看并审计；账号切换不是切换微信登录账号（平台不支持）。

【账号与数据】
- 注销路径：我的→账号→注销账号（有进行中订单会被拦截）；解绑路径：我的→绑定能力→解绑；已完成订单可删除记录。
- 测试账号/测试数据仅运营者后台使用，与真实用户严格隔离，不进入真实统计与真实用户列表，并按配置清理。
```
