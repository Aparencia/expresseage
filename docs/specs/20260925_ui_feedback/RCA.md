## 1. A：会话键把客户**自动绑**上了（P1）

- **现象**：从取件清单进录件、手选另一位客户，却被"锁回前一个"，屏上并留着「这条会话只对上这个档案」。
- **根因链（五问法，4 层）**：
  1. 为什么手选后像被锁回？→ 因为**进这一屏时归属已经被自动填上了**（`customerId` 非空、`targetLabel` 显示会话命中的那位）。
  2. 为什么会被自动填？→ `pages/recognize/index.js:97` 旧写法 `const targetId = requestedId || hitId;` —— **清单入口不带 `customerId`，于是回落到会话命中 `hitId`**。
  3. 为什么清单入口没有 `customerId`？→ `pages/pickup-list/index.js` 只在"库里恰好一个客户"时才带；**没有任何"来源标记"**告诉录入页"这次是从清单来的"（无来源闸门）。
  4. 为什么会话命中会一直在？→ `app.globalData.chatKey` 被裁成**会话级存活**（为 M7"稍后在录入页生效"）⇒ 一把旧键在清单入口照样生效。
  5. 为什么屏上那句还在？→ `form-parts.preselectNote` 对**任何来源**都输出「…（这条会话只对上这一个档案）」，清单入口也照写。
- **根因（一句话）**：**归属没有"来源闸门"** —— 会话键既能绑定、又被当说明，两者混在一条路上；用户裁定的正确口径是"只有从用户档案进入才默认绑定"。
- **影响面**：所有非档案入口（取件清单、以及将来任何新入口）；错绑的代价 = 快递记到别人名下。

## 2. B：没有档案时**进不去**录入页（P1）

- **现象**：库里一个客户都没有时，点「＋ 录快件」不进去（只在清单页显示一句"先到底栏建档"）。
- **根因链**：
  1. 为什么录不了？→ 人**到不了**录入页（`pages/pickup-list/index.js:98-101`：`hasCustomers === false` 直接 `setData(errorText)` 后 `return`）。
  2. 为什么当初这么写？→ 旧假设"没有归属就存不了，进去也白跑"。
  3. 为什么不成立了？→ 录入页已经**能当场建客户**（2026-09-25 ② 内联新建），而且保存时还会引导到那颗按钮。
  4. 为什么没被门禁发现？→ 这条判断住在**页面层**（`selftest` 不 require 页面，TD-016 同族）。
- **根因（一句话）**：**入口判据停留在内联新建之前**，把一条本来走得通的路堵在门外。
- **影响面**：新用户第一次使用（没有档案 = 最常见的起点）。

## 3. C：站点回填失效（P2）

- **现象**：识别到取件码，站点格却空着（真机截图：站点是占位符、码有值）。
- **根因链**：
  1. 为什么站点没填？→ `fillFromParse` 只在 `found.stationName` 有值时才回填（"只往空框里填"的纪律本身没问题）。
  2. 为什么 `found.stationName` 空？→ 站点来自 `stations.inferStation`，它**未命中时恒返回空串**（"绝不猜点"）—— 而它的规则表（`STATION_RULES` / 线索词 + 码型）是在**转录样本**上长出来的。
  3. 为什么规则表不覆盖真机文本？→ 真机 OCR 的常见形态是"整行**包含**一个正式名"（如 `西苑一栋南面快递中心8号柜`），而 `matchBuiltinStation` 的第 ③ 步（包含且**仅包含一个**正式名）本来就是为这种形态写的 —— 但**解析器这条路没走到它**。
  4. 为什么没人发现？→ 断言用的是**转录样本**（教训卡《样本是转录的 ≠ 真机输出》）；且"码填上了、站点没填"在屏上**没有任何提示**（banner 还说"已自动填好"）。
- **根因（一句话）**：**回填只有"解析器给出正式名"这一道**，缺少"拿原文再过一次内置站点库"的第二道；且"没认出来"是静默的。
- **诚实边界**：扩解析器规则需要**真机 OCR 原文**当样本，本轮**没有**（已登记 TD-023 并给出收集办法：录入页"识别原文"卡可展开截图）。

## 4. D：回收站缺「全部彻底删除」+ 二次确认用逐字输入（P2，需求变更）

- 旧口径：逐条彻底删除，且必须**逐字打出确认词**（`PURGE_CONFIRM_WORD`）。
- 真机代价：输入法摩擦 ⇒ 要么放弃、要么乱打字；且**没有一次清空的入口**（删了多位的用户要点 N 次 × 2 步）。
- 新口径（用户裁决）：**二次确认由按钮承担**（同颗按钮点两下）+ 新增**全部彻底删除**。
- 红线约束不变：删的动作只由用户点出来；文案必须写"不可逆 + 本机没有备份/导出"。

## 5. E：主行看不出 A/B/C 后缀（P3）

- `pages/archive-list/index.wxml:22` 主行 = `{{item.building}} {{item.dorm}}`；`pages/customer-detail/index.wxml:16` 页头同样 = 楼栋宿舍 ⇒ **同宿舍的 A/B 两位在主行与页头上完全一样**（后缀只出现在副行/称呼里）。
- 根因：单源标签 `aggregate.customerLabel` 已经修好了重复问题，但**主行还没接上它**。
