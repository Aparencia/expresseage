## §2 Should

- **S1** `chatpick` 页保留一行 **U-11 仪器**（"取键：成功（2 个 id，形态 OK，指纹 …）/ 接口无此能力 / 不在聊天工具模式"），便于真机取证与后续排障。
- **S2** 档案行显示键的**指纹**（可选开关），便于人肉眼确认"这两条档案是同一个会话"。

## §3 Could

- **C1** 自动探测"同一好友的第二个会话"并提示合并（本期只做人工合并，自动探测要额外的平台依据）。

## §4 Won't（本期明确不做 + 为什么）

- **W1 不碰群场景**（群内成员键 / `opengid`）——本期业务全是 1:1 客户单聊；群语义会引入"同一人 N 个键"的复杂度，另立卡。
- **W2 不走加密通道**（`getChatToolInfo` / `getGroupEnterInfo` 明文）——官方口径是加密，解密要 session_key 或云开发 ⇒ 新依赖，与"零后端零云"立案前提冲突（RESEARCH §2.1）。
- **W3 不做自动合并/自动迁移**（同一好友多键）——官方对 id 长期不变**零承诺**，自动合并会静默并掉错误数据；只做人工"重新绑定/合并"。
- **W4 不改 `chatTools` 四项渲染栈配置**（`independent`/`renderer`/`componentFramework`/页面级 `navigationStyle`）——平台四轮读数换来的，动它 = 重演 U-1。
- **W5 不改 `chat_pick` 的 25 卡验收清单**——本任务只声明"取代关系"（V6/V7 的动线口径），验收清单的重写属 `chat_pick` 自己的 25 卡。
- **W6 不删旧入口**（从微信聊天进 `chatpick` 建档）——U-2 不成立时它是唯一起点；删它 = 自断退路。
- **W7 不动 UI 三页的布局/视觉**——本任务只加"会话状态行 + 一颗按钮 + 查重提示"，不重做界面（要改视觉走 50 卡）。
