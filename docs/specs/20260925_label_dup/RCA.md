- 起点锚点：`baab42787d434927768221a10721f290f96697ee`（= `baab427`）
- 建档日期：2026-09-25 ｜ 关联：`docs/specs/20260925_label_dup/FIX.md`（卡 31 产物）

## 1. 现象（用户真机报告）

录入页（`pages/recognize/`，标题「添加快递」）顶部 **「给谁录」那一行的值显示成 `D4 555 D4 555 A`** —— 同一个客户被拼了两遍（前半 `D4 555` = 楼区宿舍；后半 `D4 555 A` = 该客户的**称呼**）。用户原话：「**重复了 需要修复**」。

**无报错**（静默显示错误，纯 UI 症状，控制台不会有任何输出）。

## 2. 复现步骤

**A. 真机/工具（人工）**：录入页 → 看「给谁录」行 → 选一位**建档时没填称呼**的客户。
对照：选一位**填了称呼**的客户（如 `小王`）⇒ 显示 `D4 555 小王`，**不重复**（这条对照是判据）。

**B. 纯函数链（断言级，本卡实测）** —— 脚本 `%TEMP%\rca_label_dup.js`，`node <脚本> "<仓库根>"`：

```
① nextCustomerName(空称呼) => {"name":"D4 555 A","auto":true,"sequence":1}
② buildCustomerOptions     => ["D4 555 D4 555 A"]        ★【复现成功】同一客户被拼两遍
③ 复现结果                 => ★【复现成功】
④ 对照（有称呼）            => ["D4 555 小王"]             ← 分歧只在"空称呼⇒派生名"这一支
⑤ 同宿舍第二位              => {"name":"D4 555 B","auto":true,"sequence":2}
⑥ 两人标签                 => ["D4 555 D4 555 A","D4 555 D4 555 B"]  ← 仍可区分（修法必须保住）
```

⚠️ 卡 30 动作 1 要求"用户亲自复现/同屏看输出"；本轮**无交互式用户在环**，故用 **B 纯函数链**复现（派单方指定），**真机复现待用户点检**。

## 3. 根因（≥3 层，五问法）

1. **为什么显示 `D4 555 D4 555 A`？** → 标签是 `楼栋 + ' ' + 宿舍 + ' ' + 称呼` 拼出来的（`pages/recognize/form-parts.js:281`），而该客户的**称呼本身就等于 `D4 555 A`**。
2. **为什么称呼会是 `D4 555 A`？** → 建档时**称呼留空**，系统按规则**自动补名**：`utils/customer-input.js:168 nextCustomerName()` ⇒ `name = '<楼栋> <宿舍> ' + 序号后缀(A/B/C…)`（`:155` 原句：「新档案叫 `<楼栋> <宿舍> ` + 第 N+1 个后缀」）。该文件 `:158-159` 写明**必须自动起名**：`migrate` 对 `Customer.name` 的校验是"非空且 ≤20"，空名落不了库。
3. **为什么补名要带上楼栋宿舍？** → `:155-156` 原句：「为什么带上楼栋与宿舍：`3号楼 502 A` 本身就能当识别标识，而**只叫 `A` 的话在清单上完全看不出是谁（清单行只显示客户称呼）**」+ 2026-09-21 用户裁定「允许重复 此时若有用户名则直接放置，若没有则按 A-Z 顺序命名」。⇒ **派生名自带前缀是有意设计，不是缺陷。**
4. **为什么会重复？** → **两条规则分别正确、合起来错**：派生名把"楼栋宿舍"**塞进了 `name`**，而标签合成**假设 `name` 是纯人名**、又拼了一次前缀。**缺一张"标签由谁拼"的单源约定**（谁都不负责判"这段信息已经出现过了"）。
   **时间线佐证（`git log -S` 取数）**：自动补名 `ab15e0d`（2026-09-24，"批 1/21 搬运 v1 纯函数与规则表"）**先**落地；标签合成所在函数 `buildCustomerOptions` 由 `c3f2a48`（2026-09-25，**r3 修另一个 P1 的那一批**）**新增**——`git show f23518e:pages/recognize/form-parts.js` 里该函数**尚不存在**。⇒ **这是"修 A 时引入 B"的典型形态**，且当时那批的断言只喂了"有人名"的输入（`tools/selftest-wave5.js:338-343` 用的正是 `小王`/`小李`）⇒ 缺陷对全部门禁不可见。

## 5. 影响面

- **用户可见**：录入页「给谁录」行（本轮报的）；
- **同族、当前未修（超出本卡写盘范围）**：`pages/archive-list/**` 4 处（查重命中提示、重锚冲突提示、行内操作标签、换绑目标标签）—— 涉及**无称呼客户**时同样会显示重复串。**已在报告里交派单方处置**（见 §7）。
- **不受影响**：数据层（`Customer` 仍是 `building`/`dorm`/`name` 三独立字段，**无迁移**）；档案页列表行与详情页；预选/归类（按 `chatRoomId` 比对，与标签无关）。
- **为什么 P2 而不是 P1**：功能仍可用（picker 可选、标签仍可区分 A/B），不丢数据、不误归类；仅显示重复 ⇒ 卡 30 动作 4 的"边缘功能报错/体验不佳"。

## 6. 修复方案建议（交卡 31）

**单源**：在 `pages/recognize/form-parts.js` 内新增**纯函数** `customerLabel(customer)`，由它**独占**标签合成口径，`buildCustomerOptions` 改为调用它：

```
prefix = 楼栋 + ' ' + 宿舍 + ' '
name 已经以 prefix 开头（= 空称呼自动补名的派生名）⇒ 只出 name
否则                                                   ⇒ prefix + name（原行为不变）
```

- 为什么这是**最小改动**：只改一个函数块 + 一个纯函数，行为对"有人名"的客户**逐字不变**，不碰数据层、不碰 wxml、不碰自动补名规则（那条有用户裁定背书）。
- **⛔ 不做**：不改 `nextCustomerName`（会让清单行认不出人）；不改档案页那 4 处（越界）。
- 已知残余（**登记建议**，本卡不改）：建档后若**改了楼栋/宿舍**，派生名的前缀会与字段不再一致 ⇒ 该客户标签会重新出现"前缀 + 旧派生名"的重复形态。根因与本案同源（`name` 里存了冗余定位信息），彻底解法要另立卡（要么 `name` 不再带前缀 + 清单行改为拼三字段，要么给 `Customer` 加 `autoNamed` 标志）。
