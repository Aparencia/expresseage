### 2.1 `startBatchRecognize`：任一步 reject 时 `recognizing` 会不会复位？（结论：**会**）

- 判据位置：`pages/recognize/recognize-flow.js:210-222`（`return step(0).then(...).catch(...)`），
  复位靠 `onRecognizeFailed`（同文件 `:226-228` 写 `recognizing: false`）。
- 复算（探针，三个"断链"场景各跑一次）：

```text

{"label":"A 三张：第2张 ocr reject（链条中断）","recognizing":false,…,"banner":"批量识别异常：VKSession 炸了 —— 下面的格子照旧能手填，手填也算录进来。","drafts":[],"lines":[],"ocrCalls":2}
{"label":"C 三张：第2次 planParsePatch 抛异常（零件炸）","recognizing":false,…,"banner":"批量识别异常：MUTANT: planParsePatch 内部炸 …","drafts":[],"ocrCalls":2}
```

⇒ `ocr` reject、`planParsePatch` 抛异常、`privacy` reject 三类都会走到终点 `.catch` ⇒ **`recognizing` 一定复位**，
不存在"整屏点不动"。⚠️ 我第一版探针里假页面**没带** `onRecognizeFailed`，读数一度是
`HARNESS_REJECTED: "this.onRecognizeFailed is not a function"` + `recognizing:true` —— 那是探针缺陷，不是生产缺陷
（真页面由 `index.js:417` 的 `Object.assign(..., recognizeFlow.pageMethods, ...)` 并进该方法）。
⇒ **这条判据本身没有机器闸**：它只在运行时成立，任何断言都够不到（页面层零断言 TD-016 的老债）；
真要钉，只能把"复位"抽成一个可断言的纯函数。

- 顺带一条**如实记的代价**：链条中断时（A/C）**已识别成功的那几张结果被整批丢弃**
  （读数里 `drafts: []`、`recognitionUsed: false`，而 `ocrCalls: 2` 说明前两张真的识别过了）。
  `.catch` 只报错、不复用已累积的 `batches`。这是"失败安全"的取向，可接受，但**SCOPE M7"一张失败不阻断"只覆盖
  `ok:false`，不覆盖"抛异常/reject"**。⚠️ 现有断言：**无**。

### 2.4 `utils/migrate.js` 的"只动 `stationName`"在**键序**上成立吗？（结论：**值域成立；键序上是一条过严判据**）
